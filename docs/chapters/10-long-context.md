# 10 长上下文：可见范围、信息传播与任务能力

前一章讨论如何测量同一计算的实现效率。本章进一步改变计算本身：如果一个位置不再读取所有历史位置，而只读取附近的窗口，会发生什么？答案不只是“更省内存”。掩码改变了信息可以经过的路径，也改变了模型在不同距离上完成任务的条件。

长上下文至少包含三个问题：程序能否接受那么长的输入，模型内部是否存在传播远处信息的路径，以及经过训练的模型能否完成需要那段信息的任务。这三个问题不能靠同一张检索示例或一项速度数字同时回答。本章先把它们拆开，用小张量建立可以核对的结论，再说明怎样扩展到真正的能力评测。

## 学习目标与先修关系

本章需要第 02 章的因果注意力、第 06 章的位置编码，以及第 08 章的分块推理与缓存概念。实验只依赖标准库与 PyTorch，可以独立运行，不需要先执行这些章节的代码。

读完后应能完成以下工作：

- 用绝对位置写出全局、滑窗和混合层的因果掩码，说明窗口是否包含自身。
- 推导连续局部层的最大可达距离，区分图上的路径和模型实际利用信息的能力。
- 用完整前向对照检查分块推理，定位过早裁剪缓存造成的错误。
- 设计距离可控、无答案泄漏的检索评测，并说明合成任务的局限。
- 区分上下文长度配置、位置编码外推和经过验证的任务表现。

本章没有训练一个长上下文模型，也没有复现 ZGCM-1 或其他真实混合架构。实验中的内容寻址检索是刻意构造的参照系统，用于隔离掩码造成的限制，不能作为语言模型能力成绩。

## 1. 用绝对位置定义窗口

设 Query 的绝对位置为 $i$，Key 的绝对位置为 $j$。标准因果全局注意力允许所有历史及当前位置：

$$
M_{ij}^{\mathrm{global}}=[0\le j\le i].
$$

方括号表示一个布尔条件。若滑动窗口大小 $W$ **包含当前位置自身**，则允许范围为：

$$
M_{ij}^{\mathrm{local}}=[0\le i-j<W]
=[\max(0,i-W+1)\le j\le i].
$$

例如 $W=3$，位置 5 可读取 3、4、5，不能读取位置 2，也不能读取位置 6。序列开头没有足够历史，位置 0、1 分别只能读取 1、2 个位置。窗口的实际行长度因此是 $\min(i+1,W)$，不是每一行都恰有 W 个有效 Key。

有的实现把“窗口大小”定义为历史 Token 数，再另外包含自身，这会得到 $W+1$ 个可见位置。因此阅读论文、配置和代码时要同时检查公式与实际掩码，不能仅凭字段名判断。

配套脚本使用绝对位置构造：

```python
distance = query_positions[:, None] - key_positions[None, :]
allowed = distance >= 0
if window is not None:
    allowed = allowed & (distance < window)
```

Query 与 Key 的长度可以不同。这点对缓存推理很重要：当前 Query 可能只有两个位置，Key 却包含它们之前的一段历史。直接对一个 `[2, T]` 矩阵调用默认下三角操作，得到的是局部数组索引关系，不一定是所需的绝对因果关系。

本实验采用 SDPA 的布尔掩码语义：`True` 表示允许参与注意力。其他接口可能采用相反语义。显式写出 `allowed`，并用手算的几行样例核对，比记住一个容易混淆的 `mask` 名字更可靠。

## 2. 先验证掩码改变了哪一份计算

Q、K、V 的形状为 `[B,H,T,d]`，分数矩阵为 `[B,H,T,T]`。对每一行，先排除不可见位置，再在剩余位置上归一化：

$$
A_{ij}=\operatorname{softmax}_j\left(
\frac{q_i^\top k_j}{\sqrt d}+b_{ij}\right),\qquad
b_{ij}=\begin{cases}0&M_{ij}=1\\-\infty&M_{ij}=0.\end{cases}
$$

输出为 $z_i=\sum_j A_{ij}v_j$。把某个 Key 屏蔽后，不只是删去它的 Value 贡献，其他可见 Key 的权重也会重新归一化。因而“全局结果减去窗口外的那一项”通常不是正确的局部结果。

脚本建立了三条计算路径：批量矩阵计算、逐 Query 取出合法 Key 的行参考，以及 PyTorch SDPA。先检查全局掩码，再检查局部掩码。对同一个随机输出探针求导，比较 Q、K、V 的全部梯度，以避免只验证一组前向数值。

这里不使用 dropout，也没有 padding，全局和局部的每一行至少包含自身，因此不会出现全屏蔽行。支持 padding 的生产实现还需要处理 Query 是否有效、Key padding 与因果掩码如何组合等问题；不能把本章的无 padding 代码直接当作完整服务端实现。

## 3. 局部层叠加后的可达范围

一层局部注意力最多向前移动 $W-1$ 个位置。若连续 L 层都使用相同窗口，且每个合法连接都可能传递信息，那么位置 i 能从原始输入接收信息的范围最多是：

$$
\max(0,i-L(W-1))\le j\le i.
$$

内部位置的可达 Token 数为 $L(W-1)+1$，还要受序列起点截断。注意它不是 $W^L$：虽然存在许多路径，路径的最远位置距离却是逐层相加。

以 $W=3,L=2$ 为例，位置 4 的第二层可以读取第一层位置 2、3、4；这些位置又分别读取自己的三个局部输入。合起来，原始位置 0—4 都可能影响最终位置 4。原始位置 0 仍不能影响最终位置 5，因为需要跨越的距离为 5，而两层最多跨越 4。

可用布尔矩阵乘法验证。令 $R^{(0)}$ 为单位矩阵，行表示当前输出位置，列表示最初输入位置。第 l 层的掩码为 $M^{(l)}$：

$$
R_{ij}^{(l)}=\bigvee_k\left(M_{ik}^{(l)}\land R_{kj}^{(l-1)}\right).
$$

脚本用整数矩阵乘法后判断是否大于零，实现这份布尔可达性计算。由于所有掩码都包含自身，残差连接不会扩展这里的最远可达范围；若设计不含自身的稀疏图，则还需要把残差的自连接单独加入分析。

这只回答“存在一条结构允许的路径”。它没有说明该路径在训练中学到了什么，也没有说明信息经历多次归一化、投影和非线性后是否仍容易恢复。

## 4. 图上可达与数值影响不是同一件事

如果一个输入在图上不可达，那么它的扰动不应影响目标输出。这个结论可以变成严格的实现检查。反过来，即使图上可达，某次随机网络的输出变化也可能非常小，甚至因参数为零、抵消或激活饱和而为零。因此不能要求每条可达路径在任意参数下都产生显著影响。

为了避免把随机参数的偶然抵消误判为图结构问题，实验另建一个受控网络：Q 和 K 都为零，使每行注意力在合法位置上均匀分配；V 为输入本身，外加残差。每层是：

$$
x_i^{(l+1)}=x_i^{(l)}+
\frac{1}{|\mathcal N(i)|}\sum_{j\in\mathcal N(i)}x_j^{(l)}.
$$

这是一个用于检查信息传播的线性参照，不是完整 Transformer，没有训练，也没有声称可以完成语言任务。所有路径系数非负，便于预测一个正扰动是否能传播。

快速模式用 $T=12,W=3,L=2$。把输入位置 0 的第一个特征加 1，观察各位置变化：

- 位置 4 恰在最远可达边界，变化约为 $1/9$。
- 位置 11 不可达，变化严格为 0。
- 将最后一层换成全局因果注意力后，位置 11 可以接收来自位置 0 的变化。

混合网络的远处变化不简单等于 $1/T$，因为前一层已将扰动传播到多个位置，最后的全局层会从多个路径汇总它。观察数值之前，应先画出或计算这些路径，而不是只根据“有一层全局”猜一个系数。

## 5. 混合层的顺序需要写清楚

全局层能直接读取全部历史，局部层只读取窗口。混合模型常用一部分局部层降低计算或缓存成本，再保留部分全局层维持远距离访问。描述实验时应写出完整层序列，例如：

```text
local → local → global
```

只写“2:1”并不充分：它可能表示两个局部层后接一个全局层，也可能使用别的起始位置与周期约定。全局层放在早期还是末尾，还会影响信息在随后层中的变换方式，不能认为只要数量相同，输出和能力就应等价。

快速模式比较 `local → local` 与 `local → global`；常规模式比较三个局部层与 `local → local → global`。两种混合栈的布尔可达性都是因果全局范围，但这不意味着它们等价于每层全局的网络，更不意味着能继承后者的任务成绩。

实际模型还可能保留全局 Token、使用膨胀窗口、分块稀疏连接或门控机制。每增加一种连接，需要重新写掩码、分析可达性，并说明缓存策略。普通周期性 SWA 只是一种教学配置，不是对 ZGCM-1 等模型中门控设计、训练配方和其他模块的复现。

## 6. 理论连接数与真实速度分开记录

全局因果注意力每层的合法 Query-Key 对数为 $T(T+1)/2$。包含自身的滑窗连接数为：

$$
E_{\mathrm{local}}=\sum_{i=0}^{T-1}\min(i+1,W).
$$

若 $T\ge W$，可写为 $WT-W(W-1)/2$。快速实验中 T=12、W=3，全局有 78 个合法连接，局部有 33 个；常规 T=20、W=4，分别为 210 与 74。

这些数字描述结构允许的连接，不是本脚本实际执行的乘加数。本脚本为便于数值对照，仍先计算完整 `[T,T]` 分数矩阵，再把窗口外位置屏蔽。它没有使用稀疏或滑窗专用内核，因此不能凭连接数比例声称获得相同的速度或内存收益。

在真正的局部实现中，注意力计算可按窗口组织，理想情况下随 T 线性增长、随 W 线性增长；但实际速度还受内核、数据布局、块边界、batch、精度和硬件限制。混合模型中各层的窗口和全局比例不同，缓存也必须按层分别统计。理论优势需要使用第 09 章的测量方法重新验证。

## 7. 缓存裁剪为什么必须考虑整个 Query 分块

单步解码时，局部层只需保留当前窗口有关的 Key、Value。分块解码时却有多个 Query，各 Query 需要的历史窗口不同。若把缓存先裁成“最后一个 Query 的最近 W 个 Key”，可能删去分块前部仍然需要的历史。

例如 W=3，当前分块包含位置 10、11：

| Query | 合法 Key |
| --- | --- |
| 10 | 8、9、10 |
| 11 | 9、10、11 |

如果计算前只保留 9、10、11，位置 10 会失去 Key 8。它仍有合法 Key，因此程序不会报错，也不一定出现 NaN，但结果已经偏离完整前向。这种错误很容易躲过形状检查。

正确做法之一是先保留整个分块需要的 Key 并集，也就是从最早 Query 的窗口起点开始，结合每行的绝对位置掩码完成计算；分块结束后，再按下一次调用所需的策略裁剪。设分块最早 Query 位置为 $i_0$，需要的最早 Key 是 $\max(0,i_0-W+1)$。即使缓存里暂时包含较晚的 Key，也必须由每行因果掩码防止 Query 读取未来。

实验比较完整局部注意力的最后两个输出、正确保留窗口并集的分块实现，以及过早裁剪的错误实现。错误实现最后一个 Query 仍然正确，前一个 Query 却发生明显变化。这说明只核对分块最后一个位置是不充分的，应该检查全部输出位置。

## 8. 构造检索参照，隔离“根本看不到”的问题

有了可达性和数值传播检查，仍然不能写“模型已经学会检索”。实验增加一个内容寻址参照，目的只是说明注意力掩码如何阻止访问已知目标。

我们为每个记录分配一个正交 one-hot Key。最后一个 Query 被直接设置为第一个 Key 的 20 倍，使目标记录 logit 为 20，其余为 0。这里刻意将分数尺度设为 1；不是前面随机注意力实验中默认的 $1/\sqrt d$。目标 Value 为 100，其余记录为各自的位置编号。

全局掩码允许读取目标，softmax 几乎把全部权重放在它上面，输出接近 100。局部掩码把目标排除，目标权重严格为 0，输出只能由窗口内的值组成。快速模式最后窗口为位置 9、10、11，因此输出恰为 10。

这个系统已经由我们手工给出了正确 Query、可区分的 Key 和目标分数差距，既没有从文本学习，也没有测试语言理解。报告字段显式记录 `trained: false`。它能证明本次掩码约束下，目标位置是否有直接读取机会；不能证明某个训练模型在某距离上的真实准确率。

真实检索评测需要由模型根据任务描述产生 Query，需要从相似内容中识别证据，还需要输出答案。多记录干扰、别名、格式变化、相关但不匹配的干扰项，都会使任务比这个参照更复杂。

## 9. 位置编码外推有自己的条件

程序支持更长的位置索引，只说明数学运算或缓存容量允许它。模型训练时见过的位置范围、相对距离分布与任务类型，都影响超出训练长度后的表现。

以旋转位置编码为例，一对特征按位置 p 和角频率 $\omega_r$ 旋转，角度为 $p\omega_r$。修改基频、缩放位置或调整不同频段，会改变训练过的位置关系与外推位置关系。不能只把 `max_position_embeddings` 改大，就宣称学会了利用更长上下文。

一份外推实验至少记录：原训练长度、继续训练长度与 Token 数、最终评测长度、具体频率或缩放方法、精度、注意力模式和缓存规则。若调整后同时增加训练量，收益也可能来自额外数据和优化；应把“直接改配置”和“配套继续训练”分别比较。

本章代码没有实现或验证 RoPE 外推方法。第 06 章的旋转性质与第 08 章的位置偏移一致性，是实现正确性的基础，却不能替代跨长度任务评测。

## 11. 从实验走向任务评测

如果要训练并比较全局与混合模型，可先设计距离可控的关联任务。为每个样本生成独立记录、干扰项和 Query，记录目标距 Query 的距离，再按距离区间汇总准确率。训练／验证必须在生成规则允许的范围内保持独立，不把同一条记录换个位置后当作新验证样本。

控制答案泄漏：目标值不应在 Query 或其他提示字段中重复出现；样本构造器不应总把目标放在固定位置；特殊分隔符不应编码答案索引。将距离拉长时，也要保持干扰项难度、目标数量和输出格式的可比性，否则性能变化可能来自任务本身的改变。

对真实文档，可评测定位证据、跨段关联、顺序推理与长文摘要等不同任务。检索准确不代表理解复杂论证，困惑度稳定也不代表能正确引用远处证据。报告训练和评测数据来源、去重规则、是否有基准污染，以及样本数和不确定性，遵守数据许可。

成本同样按距离和长度记录：实际处理 Token、prefill 延迟、decode 条件、每层缓存、峰值内存。局部计算可能减少单层读取，但也可能需要更多层或额外全局模块维持能力；比较时遵循[统一实验规范](/experiments)，指定主要预算而不是挑选对某个方案最有利的指标。

## 常见错误与定位顺序

窗口差一位时，先手算开头和中间位置的合法 Key；缓存分块有差异时，打印绝对 Query／Key 位置，而非只看数组长度。只有最后一个 Query 通过时，优先检查过早裁剪。若局部网络受到图上不可达输入的影响，检查窗口外权重是否真正为零、是否存在未纳入分析的全局连接。

如果图上可达但实际任务失败，不能直接断言 mask 写错。先检查模型是否训练过该长度、是否能理解任务、位置编码是否合适，再区分优化失败与结构瓶颈。不要通过加长提示、挑选个别成功示例或删去难样本来替代系统评测。

## 练习与提示

1. **推导不同窗口的堆叠范围。** 每层窗口为 $W_1,\ldots,W_L$ 时，最远历史距离是什么？提示：沿任意路径逐层累加每层最多前移的距离，边界仍需裁到 0。
2. **验证窗口等于 1。** 修改实验，让每个位置只能读取自身。提示：无论堆叠多少局部层，都不应接收别的位置扰动；原先边界检查也要随配置重新定义。
3. **扩大解码分块。** 将分块从 2 改为 4，说明计算前需要保留哪段 Key。提示：以最早 Query 为起点求窗口并集，不以最后一个 Query 为起点。处理可能出现的全屏蔽错误分支，避免把 NaN 当作正常误差。
4. **改变全局层位置。** 比较 `global → local` 与 `local → global`。提示：可达性可能相同，但受控网络的路径系数、随机网络输出一般不同；分别报告两种证据。
5. **加入更难的干扰项。** 让检索 Key 不再正交，而是具有相似向量。提示：这会同时改变内容匹配难度，不再只是掩码的对照，应将其作为另一项实验。
6. **拟定一个外推报告。** 不必立即训练，先列出训练长度、评测长度、位置编码、额外 Token 预算和距离分桶。提示：把尚未执行的部分标为计划，不填写虚构结果。

完成本章后，你应能把“支持长输入”拆成实现、传播和任务三个层面，并用不同检查分别验证。下一章的 MoE 会改变另一种计算范围：不同 Token 不再经过完全相同的前馈参数，路由与容量也需要单独验证。
