# 09 性能测量与高效实现

一个计算公式可以有多种实现。先保证实现语义一致，再评价速度、显存和适用范围。

## SDPA 与 FlashAttention 的位置

SDPA 是 PyTorch 提供的缩放点积注意力接口；实际使用哪个后端取决于硬件、dtype、shape、mask 和框架版本。FlashAttention 通过分块与数据访问优化，避免把完整注意力矩阵反复写入显存。

它主要改变计算方式，不应与改变 KV 头组织的 GQA 或改变可见范围的 SWA 混为同一类改动。使用它也不自动缩短 Decode 的 KV Cache。

## 一个可信的计时过程

1. 固定硬件、精度、batch、序列长度与实现版本。
2. 预热，区分编译／首次调用与稳定运行。
3. GPU 操作通常异步，使用合适的设备计时或显式同步。
4. 重复测量并报告分布，不只选最快一次。
5. 说明是否计入分词、数据传输、采样和服务调度。

## 分别报告哪些指标

| 场景 | 需要明确的内容 |
| --- | --- |
| 训练 | 有效 Token/s、前后向与优化器是否计入、峰值显存 |
| Prefill | 提示长度、批量、完整 Prefill 延迟 |
| Decode | 上下文长度、生成长度、单步延迟分布、批量 |
| 显存 | allocated／reserved、峰值、模型与缓存是否预分配 |

服务端 TTFT 还可能包含排队、分词和其他开销，不应直接当作纯 Prefill 时间。吞吐率与交互延迟也不是同一指标。

## 先建立数值对照

让手写实现与优化实现使用相同输入、权重、mask 和 dropout 配置。先通过正确性检查，再测量收益。若两个实现访问范围不同，速度差异不能单纯归因于优化。

## 验收标准

能复述一次测量的完整条件，区分首次与稳定运行，以及算法、实现和硬件三个层面的变化。当前讲义不提供未经执行的性能数字。
