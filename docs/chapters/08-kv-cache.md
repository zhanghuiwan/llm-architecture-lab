# 08 自回归推理与 KV Cache

生成第 $t$ 个新 Token 时，历史 Token 的 K/V 通常可以复用。KV Cache 保存这些中间状态，减少逐步生成时对历史投影的重复计算。

## Prefill 与 Decode

Prefill 处理提示词并初始化缓存；Decode 使用新增 Token 的 Query，读取历史与当前 K/V。两者的计算形状、批量与瓶颈不同，应分别测量。

```text
提示词：K[0...P-1], V[0...P-1] → 写入缓存
新增一步：Q[P] 查询 K[0...P], V[0...P]
再下一步：Q[P+1] 查询 K[0...P+1], V[0...P+1]
```

## 最容易出错的两个位置

**位置编号。** 使用 RoPE 时，新 Token 应使用完整序列中的位置，不是每次 Decode 都从 0 开始。

**非方形 mask。** 假设已有长度为 $P$ 的缓存，新输入块长度为 $Q$，那么新块中位置 $i$ 可读取 Key 位置 $j\le P+i$。不要无条件套用完整序列的左上角三角 mask。

## 一致性检查

1. 使用相同权重、相同输入和 eval 模式。
2. 完整前向计算整段序列，保留每个位置的 logits。
3. 先 Prefill，再按单 Token 或多个 Token 的块增量计算。
4. 对齐位置后比较 logits；先用 FP32，之后再检查低精度误差。
5. 覆盖空缓存、不同提示长度、分块输入和批量边界。

比较 logits 比只比较最终采样文本更可靠。微小数值差异可能在采样中放大，得到不同文本，并不自动说明缓存实现错误。

## 缓存的生命周期

明确缓存归属、有效长度、容量和设备。不要把前一请求的缓存用于无关请求；批量中不同样本长度不一致时，位置和 mask 也需要逐样本处理。缓存还可能带来容量管理与内存碎片问题。

## 验收标准

完整重算与增量推理在明确容差内一致，支持正确的位置偏移，并能说明缓存减少了哪些重复计算、仍保留了哪些代价。
