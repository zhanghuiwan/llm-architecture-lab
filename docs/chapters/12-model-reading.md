# 12 把真实模型的配置、公式与源码对应起来

目标不是从头到尾阅读一个大仓库，而是定位一个具体模型变体的计算路径，区分架构、训练配方和推理系统。

## 为每个案例固定身份

记录模型名称、Dense／MoE 类型、配置文件来源、源码 tag 或 commit、权重版本和许可证。一个系列可能包含多代多种结构，“Qwen 架构”或“DeepSeek 架构”不是足够精确的实验标识。

## 案例一：Qwen3 Dense

建议先选一个具体 Dense 变体，对照其配置查找隐藏维度、头数、KV 头数、中间维度、位置编码与权重共享等字段。

至少追踪 Embedding → Block → Q/K 归一化 → RoPE → Attention → MLP → 最终归一化 → 输出头。Qwen3 的参考实现包含独立 QK-Norm，不能只凭现代 Block 的概括替代源码核对。

对照资料：[Qwen3 官方仓库](https://github.com/QwenLM/Qwen3)、[Transformers v4.51.3 中的 Qwen3 实现](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen3/modeling_qwen3.py)。这是一个固定版本的分析入口，不代表所有未来变体。

## 案例二：DeepSeek 的 MLA 与 MoE

从 DeepSeek-V2／V3 的报告入手，先分开研究两个问题：注意力如何组织与缓存；FFN 的计算如何分配给专家。

MLA 的理解需要结合低秩表示、位置编码处理和推理时权重吸收等实现细节。不同实现缓存的实际内容可能不同，不应直接套用标准 GQA 的缓存公式。

V3 还涉及训练系统与其他训练目标。逐项标明哪些属于本次实现范围，哪些只完成论文阅读。参考：[DeepSeek-V3 官方仓库](https://github.com/deepseek-ai/DeepSeek-V3)。

## 一张固定的源码阅读表

| 问题 | 需要写下的证据 |
| --- | --- |
| 配置是什么 | 具体字段、数值和来源版本 |
| 如何计算 | 核心公式、输入输出 shape、源码符号 |
| 改了什么 | 相对基线的明确差异 |
| 为什么这样改 | 原报告的目标与实验依据 |
| 有什么代价 | 能力、计算、显存、通信或实现限制 |
| 我验证了什么 | 阅读、数值检查、训练、性能分别记录 |

## 验收标准

完成一个具体变体的逐层映射表，并区分作者的实测结论、自己的实测结论和仅有的理解假设。下载完整大模型或复现大规模训练不是本章的必要条件。
