# 04 建立可信的训练基线

网络结构实验需要一条可追溯的基线。loss 降低只是起点，还要知道它来自什么数据、消耗多少预算、是否泛化，以及中断后能否继续。

## 先固定数据边界

训练集与验证集应在生成训练窗口之前，按文档或合适的数据单位划分。先切窗口再随机划分，可能让高度重叠的文本同时进入训练与验证。记录数据版本、去重与清洗规则，检查许可与个人信息。

## 最小训练配方

采用明确记录的优化器、学习率、调度、权重衰减与梯度裁剪。先用 FP32 跑通小模型，再引入混合精度。梯度累积时说明 loss 如何缩放；根据有效 Token 数进行统计，而不是简单平均长度不同的 batch loss。

$$
N_{tokens}=N_{steps}\times B_{effective}\times T
$$

这个简式只适用于固定长度且所有位置都计入预算的情形。存在 padding、动态长度或 loss mask 时，应额外记录实际有效 Token 数。

## 每次训练记录什么

| 类别 | 最少记录项 |
| --- | --- |
| 模型 | 配置、实际参数量、源码版本 |
| 数据 | 版本、Tokenizer、长度、样本拼接和 loss mask |
| 优化 | 优化器、学习率曲线、批量、精度、裁剪 |
| 结果 | train/validation loss、Token 数、时长、峰值显存 |
| 环境 | 硬件、框架与依赖版本、随机种子 |

## 检查点与恢复

保存模型参数还不足以精确恢复训练。通常还需要优化器、调度器、混合精度 scaler（若使用）、随机数状态、训练位置和数据顺序信息。

做一次短实验：连续训练若干步；再从中间检查点恢复，比较之后的输入与损失轨迹。非确定性算子可能影响逐值一致，因此必须说明恢复目标和允许误差。

## 验收标准

可以从配置重跑一条基线；训练与验证数据边界清楚；没有 NaN/Inf；能恢复训练，并解释恢复前后的差异。先达到这一条件，再讨论新模块是否更好。
