# 11 MoE 入门：把计算分配给不同专家

MoE 通常用多个专家 FFN 替换某些 Dense FFN，并由 Router 为每个 Token 选择参与计算的专家。

## 路由与聚合

设隐藏表示为 $x$，Router 产生专家分数，选出集合 $S(x)$：

$$
y=\sum_{e\in S(x)}g_e(x)f_e(x).
$$

$f_e$ 是专家，$g_e$ 是聚合权重。分数使用什么激活、Top-K 后是否重新归一化、是否加入共享专家，都要按具体设计说明。

## 三种预算不能混为一谈

- **总参数量**影响权重存储与优化器状态。
- **激活专家数量**影响每个 Token 的专家计算，但不等于整个模型所有计算。
- **实际耗时**还包含路由、重排、设备通信和负载不均衡。

比较“总参数相近”的 Dense 与 MoE，和比较“每 Token 计算相近”的两者，是不同实验。

## 教学实现的顺序

先用很少的专家和小张量，允许朴素循环：计算路由 → 收集各专家收到的 Token → 执行专家 → 依据原始索引聚合。用可手算的例子检查分配、权重和梯度，不急于优化批处理。

然后记录各专家的 Token 数、负载分布与随训练的变化。是否设置容量限制、如何处理溢出 Token、是否有丢弃，都必须明确。

## 负载均衡

辅助损失和不依赖辅助均衡损失的路由调节方法，是不同机制。后者不代表整个训练目标中不存在任何辅助项。学习真实模型时逐项核对，而不是仅根据名称推断。

## 验收标准

正确实现一个小型 Top-K MoE，说明路由与聚合规则，提供负载统计，并明确与 Dense 对照时选择了哪一种预算。专家并行与 All-to-All 作为后续系统专题。
