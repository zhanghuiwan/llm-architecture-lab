# 00 必要准备：把张量当作计算地图

理解网络结构，不只是记住“用了注意力、用了残差”。你需要能回答：每个轴表示什么，哪个操作混合了哪些位置，参数在哪里共享，某个标量损失如何影响一组权重？这些问题最终都会落到张量、数值和梯度上。本章先建立一套可执行的检查方法，后面的语言建模、GPT、GQA 与 KV Cache 都会复用它。

本章配套一个不需要数据集、不需要显卡的独立实验。它刻意使用很小的张量，把形状、广播、数值稳定性和自动求导拆开验证。我们先追求能够说明“为什么对”，然后才考虑让实现更快。

## 你需要知道什么

先修要求是 Python 的函数、循环、列表与基本类用法，以及矩阵乘法和导数的含义。如果你已经训练过目标检测模型，可以把本章视为从图像张量切换到序列张量的一次校准，不必重新学习一整套深度学习入门课程。暂时不需要知道完整 Transformer 的组成，也不需要安装模型库。

完成本章后，你应当能够：

- 给 `[B,T,D]` 和 `[B,H,T,d_h]` 的每个轴命名，说明拆头与合头为什么可以无损恢复。
- 由矩阵乘法规则推导注意力分数和加权和的形状，指出 softmax 应沿哪个轴计算。
- 判断广播到底在复用哪一份数据，发现形状合法但语义错误的实现。
- 解释大 logits 为什么容易导致指数溢出，以及全屏蔽行为什么不能靠减最大值修复。
- 用一个独立的数值对照检查自动求导，并区分 `eval()`、`no_grad()` 和梯度清零。

这些要求是后续实验的最低工具集，不是要求你现在熟练背诵所有 API。遇到一个新操作时，先写轴的含义，再看程序输出，会比根据报错不断尝试 `reshape` 更可靠。

## 1. 从图像的空间轴切换到序列的位置轴

检测网络通常处理 `[B,C,H,W]`：批次、通道、高度、宽度。语言模型常处理 `[B,T,D]`：批次、序列位置、隐藏特征。这里的 $T$ 表示输入中有多少个位置，$D$ 表示每个位置用多少个数表示。一个位置在当前层的向量不等同于一个固定词的含义，它会随层数、上下文和参数改变。

| 记号 | 含义 | 本章快速实验 |
| --- | --- | --- |
| $B$ | 独立样本的数量 | 2 |
| $T$ | 每个样本的序列长度 | 5 |
| $D$ | 每个位置的隐藏维度 | 12 |
| $H$ | 注意力头数 | 3 |
| $d_h$ | 本章每个头的维度，$D/H$ | 4 |

我们特意让 $T=5$、$d_h=4$，避免把两个没有关系的轴设成同一个数字。有些错误只有在维度不相等时才会暴露。例如，如果你把序列轴和头维度交换后仍能进行矩阵乘法，不能据此认定实现正确；可能只是碰巧设置了相同大小。

在本章的常规多头表示中，$D=H d_h$。这是这里的结构约定，不是所有现代模型不可违反的数学定律。后续阅读真实模型源码时，还要检查投影输出维度和独立配置的 `head_dim`，不要直接把本章的简化假设套到每个架构。

批次轴通常不应参与样本之间的信息交换。对第一个样本做修改，不应该改变第二个样本的输出，除非模块明确设计了跨样本操作。序列轴则不同：注意力会让一个位置读取同一样本中的其他位置；逐位置线性层只改变最后一维，参数在各位置间共享。区分“共享参数”和“交换信息”，是读懂计算图的重要一步。

## 2. 拆头只是重排，投影才改变表示

从 `[B,T,D]` 拆成多头表示，分两步进行：先把隐藏维度分解成 `[H,d_h]`，再交换位置轴和头轴。

```python
B, T, D, H = 2, 5, 12, 3
x = torch.randn(B, T, D)
w = torch.randn(D, D)
projected = x @ w
q = projected.reshape(B, T, H, D // H).transpose(1, 2)
assert q.shape == (B, H, T, D // H)
```

`x @ w` 才是真正的线性投影：它用同一个矩阵变换每个位置的特征。`reshape` 与 `transpose` 没有加入新的可学习参数，只改变已有数值的逻辑组织方式。拆头后，如果按相反顺序合头，应能恢复 `projected`，而不是恢复投影之前的 `x`。

```python
joined = q.transpose(1, 2).contiguous().view(B, T, D)
torch.testing.assert_close(joined, projected)
```

在 PyTorch 中，`nn.Linear(in_features, out_features)` 的权重存储形状是 `[out_features,in_features]`，模块内部相当于乘权重的转置。本章直接建立 `[D,D]` 的张量并执行 `x @ w`，是为了让下标关系更直观。阅读其他代码时要先判断权重的存储约定，再比较公式，不能仅凭两段代码都叫 `weight` 就逐元素对照。

### 连续性为什么影响 view

张量不仅有 shape，还有 stride。stride 描述沿某个轴移动一步，在底层存储中跨过多少个元素。交换轴通常只改变 shape 和 stride，不复制数据，因此得到的张量往往不再连续。快速实验中的 `q` 形状为 `[2,3,5,4]`，stride 为 `[60,4,12,1]`：每个头内部的位置并不是沿一整块连续存储依次排列。

这时直接用 `q.view(B,H*T,d_h)` 合并头轴与位置轴，会因为布局不兼容而报错。`reshape` 可以在需要时复制数据，`contiguous().view(...)` 则明确要求先准备兼容布局。两者都不能自动修复轴顺序的语义错误：如果你合并了错误的两个轴，即使程序成功运行，结果仍可能与想要的多头拼接不同。

不要通过到处加入 `contiguous()` 代替推导。先确定目标元素顺序，再选择操作；性能优化时再测量复制是否带来实际开销。本章只检查逻辑顺序与数值恢复，不把“没有复制”当作性能结论。

## 3. 用轴标签推导矩阵乘法

给定 $Q,K,V\in\mathbb{R}^{B\times H\times T\times d_h}$，每个样本、每个头独立计算：

$$
S=\frac{QK^\top}{\sqrt{d_h}},\qquad
S\in\mathbb{R}^{B\times H\times T\times T}.
$$

这里的转置只交换最后两个轴。矩阵乘法要求收缩的维度相等：`[T,d_h] @ [d_h,T]` 产生 `[T,T]`，前面的批次轴与头轴保留。

```python
scores = q @ k.transpose(-2, -1) / (q.shape[-1] ** 0.5)
```

分数矩阵的倒数第二个轴是查询位置，最后一个轴是被读取的键位置。第 $i$ 行、第 $j$ 列回答的是“查询位置 $i$ 对键位置 $j$ 分配多大的未归一化分数”。本章先不用这个分数做语言预测，只建立计算地图。

沿最后一维执行 softmax 后，每个查询得到一份对所有键位置的权重。把这份权重与 $V$ 相乘：

$$
A=\operatorname{softmax}(S,\text{键轴}),\qquad
O=AV,\qquad O\in\mathbb{R}^{B\times H\times T\times d_h}.
$$

展开一个输出元素，就能看清收缩的下标：

$$
O_{b,h,i,c}=\sum_{j=0}^{T-1}A_{b,h,i,j}V_{b,h,j,c}.
$$

配套脚本同时用矩阵乘法和显式加权求和计算这个输出，两者应接近。对照实现刻意采用不同写法，帮助检查我们是否真的沿键位置求和。只比较两段几乎相同的 `matmul`，往往无法发现共同的轴错误。

## 4. 广播能省代码，也能掩盖错误

广播会从末尾对齐维度。两个对应维度相等，或其中一个是 1，就可以参与广播；缺失的前置维度按 1 处理。广播规则只检查大小，不知道一个轴表示批次、位置还是通道。

因果注意力允许位置 $i$ 读取位置 $j\le i$。我们先构造一个二维布尔矩阵：

```python
allowed = torch.ones(T, T, dtype=torch.bool).tril()
masked = scores.masked_fill(~allowed[None, None, :, :], -torch.inf)
probabilities = masked.softmax(dim=-1)
```

`allowed` 中的 `True` 表示允许读取；`masked_fill` 的条件中 `True` 则表示要被替换，所以这里取反。这是本段代码的约定，阅读其他 API 时应重新确认布尔 mask 的含义，而不是机械照搬取反。

`[1,1,T,T]` 会扩展到 `[B,H,T,T]`，同一份位置规则被所有样本和所有头复用。实验还会逐样本、逐头单独应用二维 mask，再与广播结果比较，确认广播没有改变规则。

实际模型还可能使用 padding mask。一个 `[B,T]` 的“哪些键位置有效”掩码，常需要显式改成 `[B,1,1,T]`，使它对应批次与键轴。把 `[B,T]` 原样丢进一个四维操作，不等于它一定会按批次轴解释：广播只从末尾对齐。即使某组维度恰好让它成功，语义也可能错位。本章实验不实现不同长度样本与 padding 的完整处理，后续数据管线需要单独验证这一部分。

### 一个必须保留的错误对照

把 `scores.softmax(dim=-1)` 改成 `scores.softmax(dim=-2)`，输出 shape 完全不变，但它归一化的是查询轴。此时每列和为 1，每行和一般不再为 1，已经不再是“每个查询对各键分配一份权重”。

脚本会明确检查这个错误例子保留 shape、却不能通过正确的行和检查。错误对照不是为了展示异常数量，而是确认我们的验收条件能区分“看上去能运行”和“执行了目标计算”。

## 5. Softmax 的稳定计算与边界

softmax 定义为：

$$
p_i=\frac{\exp(z_i)}{\sum_j\exp(z_j)}.
$$

如果 $z=[1000,1001,999]$，直接计算指数，在本实验的 FP64 中也会溢出为无穷大。之后执行无穷大除以无穷大不能得到想要的概率。因为给全部 logits 减去同一个常数不改变 softmax，我们通常减去最大值：

$$
p_i=\frac{\exp(z_i-m)}{\sum_j\exp(z_j-m)},\qquad m=\max_jz_j.
$$

此时最大指数为 1，其他指数不超过 1，避免了正方向的指数溢出。配套代码手动实现这个公式，并与 `torch.softmax` 比较，还检查 logits 整体平移前后的输出是否一致。不要在训练代码中为了演示原理而换回朴素指数公式，实际应优先使用经过实现和测试的框架算子。

稳定公式也有适用边界。如果某一行全部被 mask 为负无穷，那么不存在合法的概率分布；负无穷减负无穷会产生 NaN。脚本故意构造这一行，检查能否识别非法结果，但不会把 NaN 写入 JSON 指标。它不是一个“应该得到全零概率”的合法行。

这种情况在组合因果 mask、padding mask、缓存位置偏移时可能出现。应先保证每个被计算的查询至少有一个合法键，或者明确定义并实现对无效查询的处理，然后检查输出和损失。仅仅把 NaN 替换成零可能隐藏上游错误；更不能据此声称模型数值稳定。

## 6. 从标量损失追踪梯度

反向传播通常从一个标量损失开始。设 $X\in\mathbb{R}^{B\times T\times D}$，共享权重 $W\in\mathbb{R}^{D\times 3}$，定义：

$$
Y=XW,\qquad L=\frac{1}{3BT}\sum_{b,t,c}Y_{b,t,c}^{2}.
$$

这个目标没有训练任务含义，只用来观察一条简单、光滑、可数值检查的梯度路径。权重在批次和序列位置之间共享，所以它的梯度会汇总所有位置的贡献；输入梯度仍保留 `[B,T,D]` 的形状。

```python
x = torch.randn(B, T, D, dtype=torch.float64, requires_grad=True)
w = torch.randn(D, 3, dtype=torch.float64, requires_grad=True)
loss = (x @ w).square().mean()
loss.backward()
assert x.grad.shape == x.shape
assert w.grad.shape == w.shape
```

注意上面的 `w` 是叶子张量。如果先建立 `requires_grad=True` 的随机张量，再做缩放赋给同名变量，新变量通常不再是叶子；默认不会保留它的 `.grad`。配套脚本先完成缩放，再调用 `.requires_grad_()`，让需要检查的权重成为叶子。`None` 梯度不一定表示反向传播坏了，也可能是你在读取未保留梯度的中间结果。

另一个常见误区是以为 `backward()` 会覆盖已有梯度。默认情况下，它会累加。脚本重新建立同一个标量目标并再次反向传播，检查权重梯度是否变为原来的两倍。正常训练循环一般需要在适当位置执行 `optimizer.zero_grad()`；梯度累积训练则有意延迟清零，并相应设计损失归一化。

## 7. 用有限差分检查自动求导

只检查梯度“存在且形状正确”还不够。可以暂时脱离 autograd，把某个权重坐标 $w_i$ 加减一个很小的扰动：

$$
\frac{\partial L}{\partial w_i}\approx
\frac{L(w_i+\varepsilon)-L(w_i-\varepsilon)}{2\varepsilon}.
$$

这个近似叫中心差分。实验在 FP64 下取 $\varepsilon=10^{-6}$，检查三个不同权重坐标，并记录数值梯度与 autograd 梯度的最大绝对误差。比较时必须固定输入和其他权重，不能让两次前向使用不同随机数，也不能在中间更新参数。

为什么不用特别小的扰动？扰动过大，差分近似误差增加；扰动过小，两次损失非常接近，浮点减法消去误差会放大。选择 FP64 是为了给这个教学对照留下足够余量，不代表正式训练也要用 FP64。对低精度、非光滑函数、随机层和融合实现，需要另行制定检查方案。

有限差分只覆盖选中的三个坐标与这个具体目标，不是整个框架自动求导的证明。它的价值在于给新增算子提供一个独立、可理解的小规模对照。后续你修改归一化、注意力或路由时，可以先用类似方法排除梯度连接错误，再扩大实验。

## 8. eval 与 no_grad 解决不同问题

`model.eval()` 会把模块切换到评估模式，影响 Dropout、BatchNorm 等读取训练状态的模块；它不会自动关闭 autograd，也不会让所有操作都确定性。`torch.no_grad()` 在其作用域内关闭常见操作的梯度记录，却不会自动把 Dropout 切换为评估行为。

```python
layer.eval()
y = layer(x)              # 参数仍需梯度，y 仍可有计算图
with torch.no_grad():
    z = layer(x)          # 这里不记录这条前向的求导图
```

本章把这两件事分开检查：线性层进入 `eval()` 后，输出仍然需要梯度；在 `no_grad()` 内运行，则不记录该输出的梯度路径。另用 Dropout 验证训练模式会改变全 1 输入，而评估模式返回原输入。

进行数值等价性比较时，要同时考虑模块状态与梯度开关。两个实现若分别处于训练和评估模式，即使权重、输入、随机种子相同，也未必得到可比较的输出。固定种子有帮助，但不能替代对随机层、输入、dtype 和误差阈值的明确约定。

## 9. 运行独立实验

完整代码位于 [experiments/00-preparation/main.py](https://github.com/zhanghuiwan/llm-architecture-lab/blob/main/experiments/00-preparation/main.py)。只依赖 Python 标准库与 PyTorch，不读取仓库中其他章节、不下载模型或数据，也不要求工作目录固定。先在所用 Python 环境安装 CPU 版 PyTorch；全书环境准备见仓库的实验运行说明。

在仓库根目录执行：

```bash
python experiments/00-preparation/main.py --quick
python experiments/00-preparation/main.py
python experiments/00-preparation/main.py --quick --seed 7
python experiments/00-preparation/main.py --quick --output experiment-results/00-preparation.json
```

如果你在其他目录，使用脚本的绝对路径即可。`--output` 相对于当前工作目录解释，脚本会创建需要的父目录；它与 stdout 输出同一份 JSON。失败的断言会让程序以非零状态退出，不能只看到一部分 `true` 就当作通过。

`--quick` 使用 `[B,T,D,H]=[2,5,12,3]`，常规模式使用 `[3,7,20,4]`。两者都只做小规模 CPU 数值验证，常规模式的规模变化用于避免只对某一组形状有效，而不是模拟大模型训练。脚本设置单个 CPU 线程；本章不报告速度排行，也不比较设备性能。

输出分为四部分：`chapter` 标识实验，`seed` 标识随机种子，`checks` 给出逐项断言结果，`metrics` 记录具体形状、stride、损失和数值误差。固定的稳定 softmax 示例与随机输入无关；有限差分误差会随种子、规模和数值库产生细微变化，应判断它是否在预设容差内，而不是复制某个小数逐位验收。

本章编写时在 CPU PyTorch 2.8.0+cpu、Python 3.12 环境实际执行了快速、常规和另一个种子的模式，下列运行全部从 `/tmp` 作为工作目录，通过脚本绝对路径执行，并核对 `--output` 文件与 stdout JSON 完全一致。

| 模式与种子 | 实际结果 | 三个坐标的梯度最大绝对误差 |
| --- | --- | --- |
| quick，seed 42 | 28 项检查通过 | $1.18\times10^{-10}$ |
| 常规，seed 42 | 28 项检查通过 | $7.58\times10^{-11}$ |
| quick，seed 7 | 28 项检查通过 | $9.08\times10^{-12}$ |
| quick，seed 0 | 28 项检查通过 | $5.88\times10^{-11}$ |

快速模式 seed 42 的三个坐标最大梯度绝对误差约为 $1.18\times10^{-10}$，低于脚本的 $10^{-7}$ 阈值；行和误差约为 $2.22\times10^{-16}$。这仅描述本次小规模 FP64 验证，不代表其他精度或模型配置已经验证。

## 10. 自查、练习与进入下一章的条件

运行通过后，先不看代码，试着回答：为什么分数矩阵有两个 $T$？为什么拆头之后是 `[B,H,T,d_h]` 而不是把批次并入头？为什么 softmax 输出 shape 正确仍不能保证实现正确？这些解释比记住 28 个检查名称更有用。

| 练习 | 提示与验收方向 |
| --- | --- |
| 把快速模式的 $T$ 改为 6，其他维度不变 | 推导新 score shape，保持头维度为 4；不能为了让程序运行而改错收缩轴 |
| 用 `einsum` 重写加权求和 | 下标应体现查询 $i$、键 $j$、通道 $c$，与矩阵乘法比较，而非仅检查 shape |
| 给每个 batch 使用不同的 mask | 从 `[B,T,T]` 明确增加头轴，再与逐样本实现比较 |
| 将有限差分改为 FP32 并扫描多个 epsilon | 记录误差变化；不要预设扰动越小越好，也不要删除失败阈值来“通过” |
