# 03 组装最小 GPT

上一章回答了“一个位置如何读取之前的位置”。这一章把注意力装进一个能够训练、计算下一字符概率并逐步生成文本的完整网络。我们暂时使用可学习的绝对位置、LayerNorm 和普通 MLP，不急于引入 RoPE、GQA 或缓存。这样，每个新增结构都能与一个明确的基线比较。

本章的完成标准不是“生成的句子看起来像中文”，而是：能够解释从整数输入到损失的全部张量，核对参数量和权重共享，检验因果约束，在微型训练集上真正降低损失，并说清楚这些结果能证明什么。完整代码见 [独立实验 main.py](https://github.com/zhanghuiwan/llm-architecture-lab/blob/main/experiments/03-minimal-gpt/main.py)。它不导入其他章节，不下载语料或权重，从任意工作目录都能运行。

## 3.1 先把预测任务固定下来

先修知识是第 01 章的右移标签、交叉熵和采样，以及第 02 章的因果注意力。读到公式时，先写维度，再检查运算。实验采用字符词表；这里一个 Unicode 字符对应一个整数，而不是现实模型常用的子词 Token。字符切分是为了消除外部依赖，不能据此推断正式 Tokenizer 的压缩率或效率。

我们使用以下确定配置：

| 符号 | 含义 | 实验值 |
| --- | --- | --- |
| $B$ | 一次前向的序列数 | 4 |
| $T$ | 输入序列长度 | 16 |
| $C$ | 模型支持的最大上下文长度 | 16 |
| $V$ | 字符词表大小 | 15 |
| $D$ | 残差流宽度 | 32 |
| $H$ | 注意力头数 | 4 |
| $d$ | 每头维度 $D/H$ | 8 |
| $L$ | Transformer 层数 | 2 |

代码内置一句小语料，重复后从四个固定起点截取窗口。例如原始片段是“春天读书，夏天看海。”，输入和标签有如下对应关系：

```text
输入 x：春 天 读 书 ， 夏 天 看 海
标签 y：天 读 书 ， 夏 天 看 海 。
```

对于位置 $t$，模型看见 $x_{\le t}$，要预测的是 $y_t=x_{t+1}$。因此，输入张量和标签张量都是 `[B,T]`，但二者不能直接相同。实验首先检查 `x[:, 1:] == y[:, :-1]`。这只检查窗口内部的右移关系；每行最后一个标签还必须来自原语料的下一个字符，不能随意复制最后一个输入。

训练时一次把所有输入位置送入网络，称为 teacher forcing。它没有违反自回归约束，因为第 $t$ 行注意力只能读取第 $t$ 个及之前的输入。已知真实后续输入可以并行计算后续位置的损失，却不能让前面的位置偷看它们。生成时没有真实下一个字符可用，只能把刚生成的字符接回输入，重新执行前向。

## 3.2 从整数到残差流

模型的完整路径是：

```text
字符 ID [B,T]
  → Token Embedding [B,T,D]
  + Position Embedding [T,D]（沿 batch 广播）
  → L 个 Pre-Norm Transformer Block [B,T,D]
  → 最终 LayerNorm [B,T,D]
  → 共享权重的线性输出头 [B,T,V]
  → 与右移标签计算交叉熵，得到标量 loss
```

整数 ID 本身没有连续的语义距离。`nn.Embedding(V,D)` 是一张可学习表 $E\in\mathbb R^{V\times D}$，查表把每个 ID 变为一个 $D$ 维向量。初始残差流定义为

$$
h^{(0)}_{b,t}=E[x_{b,t}]+P[t],
$$

其中 $P\in\mathbb R^{C\times D}$ 是可学习的位置表。两项相加，而不是拼接，所以后续宽度仍然是 $D$。在 PyTorch 中，位置索引 `torch.arange(T)` 的结果为 `[T]`，查表后为 `[T,D]`；它可以与 `[B,T,D]` 广播相加。这里每一行序列从位置 0 开始，没有跨窗口延续的全局位置。

为什么需要位置？因果掩码规定了“哪些位置能读”，但不等于一个充分的位置表示。位置表让模型直接区分当前窗口中的第 0、1、2……个位置。它也引入明确限制：长度超过 $C$ 时无法查表。本实验在入口主动抛出 `ValueError`，并验证超长输入确实被拒绝，而不是悄悄截断训练样本。

绝对位置表是在训练中学出来的。若模型最大长度是 128，但训练始终只用前 16 个位置，后面的行没有获得同样的训练。本实验令训练长度与最大上下文同为 16，避免在生成时无意使用从未训练的位置行。这个选择方便调试，不代表模型已经学会处理长文本。

## 3.3 一个 Pre-Norm Block 到底做了什么

令某层输入为 $h$，一个 Block 写成

$$
a=h+\operatorname{Attention}(\operatorname{LN}_1(h)),
$$

$$
h_{\mathrm{out}}=a+\operatorname{MLP}(\operatorname{LN}_2(a)).
$$

“Pre-Norm”描述归一化在子层之前。残差相加的两条分支都必须是 `[B,T,D]`，这也是宽度固定的原因。主干保留当前表示，注意力与 MLP 学习增量；这有利于训练，但不能据此声称任意深度、初始化和学习率都稳定。

实验代码故意把这个结构写得直接：

```python
def forward(self, x):
    x = x + self.attn(self.norm1(x))
    return x + self.mlp(self.norm2(x))
```

注意两次归一化不是同一个模块。第二次归一化的输入也是第一次残差更新后的 `x`，不是最初输入。将所有操作写成一条长表达式，容易把这一点弄错。

LayerNorm 在每个位置的最后一个维度上统计均值和方差。它不会把不同序列或不同时间位置混在一起，因此不会通过归一化偷看未来。默认实现还具有可学习的缩放和偏移，各有 $D$ 个参数。后续讨论 RMSNorm 时，应保持其余结构与训练条件一致，才能判断替换的效果。

## 3.4 把因果多头注意力装进去

实验用一个 `Linear(D,3D)` 同时产生 Q、K、V，然后沿最后一维切成三块。每块先从 `[B,T,D]` reshape 为 `[B,T,H,d]`，再交换序列和头维，得到 `[B,H,T,d]`。

对于每个头，计算

$$
S=\frac{QK^\top}{\sqrt d},\qquad
A=\operatorname{softmax}(S+M),\qquad
Z=AV.
$$

这里转置的是 K 的最后两维，因此分数是 `[B,H,T,T]`。掩码 $M_{i,j}$ 在 $j\le i$ 时为 0，在 $j>i$ 时为负无穷。softmax 沿最后一个维度计算：固定一个查询位置，在所有允许的键位置之间归一化。对角线必须允许读取，因为当前输入字符本身也是预测下一字符所需的信息。

本实验采用显式布尔变量 `allowed`：

```python
allowed = torch.ones(T, T, dtype=torch.bool, device=x.device).tril()
probs = scores.masked_fill(~allowed, float('-inf')).softmax(-1)
```

这段代码的含义是“允许为 True”。它不是所有 PyTorch API 都通用的约定。尤其不要把它原样当作 `nn.MultiheadAttention` 的布尔 `attn_mask`：该接口的 True 表示阻断。混用约定经常得到形状完全正确、含义完全错误的模型。

各头结果 `[B,H,T,d]` 交换为 `[B,T,H,d]` 后，需要连续内存才能安全使用这里的 `view`，所以代码先 `.contiguous()`，再合并为 `[B,T,D]`。最终输出投影仍然是 `Linear(D,D)`，因此可以接到残差相加。输出投影使各头的信息能够混合，不应该因为拼接后维度已是 $D$ 就擅自省略。

手写计算适合检查维度与掩码，正式性能实验通常还需要高效内核。本章不比较内核速度，也不把显式构造 `[T,T]` 分数矩阵作为长上下文的推荐实现。

## 3.5 MLP 与最终输出头

MLP 对每个位置独立使用相同的两层线性变换：

$$
\operatorname{MLP}(u)=W_2\operatorname{GELU}(W_1u+b_1)+b_2,
$$

维度依次为 $D\rightarrow4D\rightarrow D$。注意力负责在位置之间传递信息；MLP 提供逐位置的非线性变换。这里“逐位置”不代表它不知道上下文，因为输入残差流已由注意力混合了上下文。

最后一个 Block 之后还有最终 LayerNorm。输出头把 `[B,T,D]` 映射到 `[B,T,V]`，每个位置得到词表上所有候选字符的 logits。logits 可以是任何有限实数，不要求相加为 1；计算交叉熵时直接传入 logits，不要先 softmax 再传给 `F.cross_entropy`。函数内部已经包含数值稳定的 log-softmax。

输出头不使用偏置，并将其权重绑定到输入 Embedding：

```python
self.head = nn.Linear(width, vocab_size, bias=False)
# 完成各模块初始化后再绑定，避免重复初始化同一个共享参数。
self.head.weight = self.token.weight
```

两者的权重形状恰好同为 `[V,D]`。查表时选取行向量，输出时计算隐藏状态与所有行向量的内积；二者使用的是同一张参数表。绑定不意味着复制数值相同的两个 Tensor，而是同一个 `nn.Parameter` 对象。若只用 `copy_` 复制初值，训练一步后就可能不同；实验检查的是 `is` 身份关系。

共享参数从输入路径和输出路径同时接收梯度，优化器只应更新一次。`model.parameters()` 会去重共享的参数，本实验也检查了参数枚举中 Embedding 对象只出现一次。不要自己把两个模块的参数列表拼接成带重复项的优化器列表。

## 3.6 精确核对参数量

忽略偏置与归一化时，每个标准 Block 大约是 $12D^2$ 个参数。本章足够小，可以把每一项都算清楚：

| 模块 | 权重和偏置参数量 |
| --- | --- |
| QKV 投影 | $3D^2+3D$ |
| 注意力输出投影 | $D^2+D$ |
| MLP 扩展层 | $4D^2+4D$ |
| MLP 收缩层 | $4D^2+D$ |
| 两个 LayerNorm | $4D$ |
| 一个 Block 合计 | $12D^2+13D$ |

共享输出头时，完整模型为

$$
P=VD+CD+L(12D^2+13D)+2D.
$$

依次是 Token 表、位置表、全部 Block，以及最终 LayerNorm。代入本章 $V=15,C=16,D=32,L=2$，得到 **26,464** 个独立参数。若解除输出头共享，会额外增加 $VD=480$ 个参数，即 **26,944**。脚本同时构造共享与不共享模型，用实际参数枚举核对两个数。

这里计数的是独立可训练标量，不是模块引用次数，也不是推理时的缓存大小。训练显存还包括梯度、优化器状态、激活和临时张量，因此不能用参数数乘以四字节就当成训练内存。随着后续替换结构，这张账单也必须更新：改变偏置、MLP 宽度、GQA 投影或位置编码都会改变相应条目。

## 3.7 损失、反向传播与最小训练循环

给定标签 $y$，本章在所有 $BT$ 个位置上平均负对数概率：

$$
\mathcal L=-\frac1{BT}\sum_{b,t}
\log\operatorname{softmax}(z_{b,t})_{y_{b,t}}.
$$

实现时把 `[B,T,V]` reshape 为 `[B*T,V]`，把标签 reshape 为 `[B*T]`。实验再独立用 `log_softmax(...).gather(...)` 提取真实标签的概率，两条计算路径必须一致。这个检查能帮助发现取错类别维或错误平均，但不能代替检查标签是否正确。

```python
optimizer.zero_grad(set_to_none=True)
logits = model(x)
loss = F.cross_entropy(logits.reshape(-1, V), y.reshape(-1))
loss.backward()
optimizer.step()
```

顺序不能随意交换。若忘记清梯度，不同迭代的梯度会累加；若在反向传播前执行优化器更新，本轮梯度还不存在。代码使用 AdamW，学习率 0.012、weight decay 0.01，快速模式训练 100 步，常规模式 220 步。这个学习率只为当前几十 K 参数的微型拟合任务设置，不能直接搬到大模型预训练。

这里不使用 dropout，以减少首次实现的随机因素；也不使用学习率调度、混合精度或梯度累积。这些机制各自解决不同问题，应在基线计算正确之后逐项引入。第 04 章会进一步讨论训练状态、恢复和可比较的实验条件。

每个训练步骤都检查所有参数是否有梯度、梯度是否有限；第一步还记录共享 Embedding 的梯度范数。最终检查所有参数有限，训练损失至少比初始损失低 75%，训练位置准确率至少 90%。这些断言是当前固定微型任务的实现验收线，不是面向其他语料的通用模型质量标准。

结果包含 `chapter`、`seed`、`checks` 和 `metrics`。本实验有 19 项检查，除训练外还覆盖以下边界：

- 改变输入的第 8 个及之后的位置，前 8 个输出 logits 应保持不变；被改变后缀的输出应该能够变化，避免拿一个完全忽略输入的模型“通过”因果检查。
- 超过最大上下文的输入必须被明确拒绝。
- 共享与不共享模型的参数量差必须等于词表大小乘以宽度。
- 生成长度与词表范围正确，最初的提示词保持原样，生成循环能够跨过最大上下文长度。

注意因果测试中的索引是从 0 开始的：修改 `[:, 8:]`，检查的是 `[:, :8]`。这是一项反事实检查，不是仅仅观察下三角 mask 是否存在。若移除 mask，未来扰动通常会传播到前面位置，检查应失败。若你自己改造实现，务必保留这种对行为的测试。

下面的数值来自 CPU PyTorch 2.8.0 的实际运行，不是期待输出的占位符；时间随机器变化，不作性能比较：

| 条件 | 初始损失 | 结束损失 | 训练准确率 |
| --- | --- | --- | --- |
| `--quick --seed 42`，100 步 | 2.768994 | 0.001555 | 1.00 |

同一程序还实际运行了 220 步常规模式、seed 7 的快速模式，以及从 `/tmp` 工作目录发起的 seed 0 快速模式；具体结果以每次 JSON 为准。若你改了 PyTorch 版本、语料、宽度或学习率，数值可能不同。检查应依据任务定义，而不是为了抄到某个小数而修改训练结果。

把固定四个窗口训练到很低损失只说明这条训练路径能够拟合它们。我们没有独立测试集，没有测量语言理解、知识或聊天能力，也没有验证生成文本的外部事实。训练准确率为 1.00 不能证明模型学会了中文，甚至不能证明它在同一短语料的其他窗口上表现同样好。

## 3.9 从单次预测到自回归生成

训练之后，模型接收一个四字符提示词，每次取最后一个位置的 logits，softmax 后用 `torch.multinomial` 抽一个字符，再拼回输入。实验生成 28 个新字符，最终长度为 32：

```python
logits = model(result[:, -model.context:])[:, -1]
next_id = torch.multinomial(logits.softmax(-1), 1, generator=generator)
result = torch.cat((result, next_id), dim=1)
```

训练与生成使用同一套参数和前向函数。区别是训练对每个位置都有真实标签，而生成时下一步的输入来自模型自己的选择。早期一次错误会改变后续上下文，所以低训练损失和流畅的自由生成不是同一项指标。

生成循环在 `torch.no_grad()` 下运行，避免构建无用的梯度图；先调用 `model.eval()` 表达推理意图。当前模型没有 dropout，因此 `eval()` 不会改变这部分计算；在有 dropout 的实现中，忘记切换会造成不同的推理行为。

当累计长度超过 16，脚本只保留最近 16 个字符，每次重新计算完整上下文。位置表也从 0 重新编号。这是一个明确的滑动窗口策略，既丢弃较早信息，又改变保留字符的绝对位置语义；不能称为无限上下文，也不能称为 KV Cache。本章只验证生成循环可运行，后面会对缓存与整段重算进行更严格的数值一致性检查。

采样使用独立的 `torch.Generator`，并由 `--seed` 初始化，避免采样结果依赖构造模型时消耗了多少随机数。固定 seed 仍不保证跨所有硬件和软件版本逐位一致，尤其不要把一条恰好好看的生成结果当作可靠结论。

## 3.10 常见失败与定位顺序

**损失几乎不降。** 先确认标签右移，再检查输出与标签 flatten 的顺序、优化器是否拿到了模型参数、是否执行了 `backward()` 和 `step()`。不要首先通过加层或换注意力来掩盖基础问题。尝试固定一个更小的 batch，而不是一边改数据一边改模型。

**损失低得反常，却无法生成。** 检查输入与标签是不是相同，因果 mask 是否颠倒，是否在输入中泄露了应预测的字符。低损失是值得解释的观测，不一定是成功。因果扰动测试能发现一类泄漏，但数据切分、重复样本与外部预处理仍需单独检查。

**出现 NaN。** 检查有没有某一行全部被 mask，softmax 是否沿正确轴计算，输入 token 是否越界，训练前是否已有非有限 logits。先用 FP32 和本章的小尺寸排除结构错误，再考虑更复杂精度配置。把 NaN 替换成 0 会隐藏问题，不能算修复。

**参数数目对不上。** 先确认输出头是否共享，线性层是否有偏置，LayerNorm 是否计入了缩放与偏移，MLP 中间宽度是否是 $4D$。特别留意参数表中重复引用与真正独立存储的区别。

**训练准确率高，生成重复。** 这个实验的语料本来就高度重复，而且目标只是拟合固定窗口。生成模式中的累计错误、温度和上下文截断也会影响表现。不要用“它能连续说话”代替验证集损失或任务评价。

## 3.11 练习与验收

1. **逐项重算参数。** 将层数改为 1，再把宽度改为 48、头数改为 6，先在纸上写预测参数量，再对照枚举。提示：改变头数但保持标准 MHA 总宽度不变，QKV 和输出投影参数量并不因此改变；head dimension 会改变。
2. **解除权重共享。** 只改变 `tied=False`，比较参数差和两张权重是否同一个对象。提示：不共享时也可能训练成功，参数更少与损失更低不是逻辑上的必然关系。比较训练效果应重复多个随机 seed，记录相同预算。
3. **制造并发现泄漏。** 暂时去掉因果 mask，观察未来扰动检查如何失败。提示：不要只看损失曲线；泄漏模型的训练损失可能更好看。完成后恢复正确实现，不把错误版本混入正式基线。
4. **检查梯度去向。** 在第一步更新前打印各层梯度范数到标准错误，找出是否有参数始终无梯度。提示：梯度大小不同不自动代表错误，但 `None` 常意味着没有进入计算图；共享参数不能被误认为只来自一个路径。
5. **引入真正的验证切分。** 另写一份无重叠文本，并在 `eval()`、`no_grad()` 下计算其平均交叉熵。提示：需要定义未知字符如何处理，不能一边用验证集扩词表一边声称完全未使用验证信息。
6. **研究窗口截断。** 固定同一长提示词，比较完整可容纳输入与只保留最近 8 个字符的最后位置 logits。提示：差异既可能来自信息丢失，也可能来自绝对位置重新编号；设计实验时要把两个因素拆开。

完成后，你应能不用背代码，画出一次前向、一次反向和一次生成的张量流，准确解释 26,464 个参数来自哪里，并用可执行断言支撑“因果、共享、能学习”这三个结论。接下来需要解决的是：如何把一个能拟合微型数据的网络，变成可以恢复、比较和诊断的训练基线。
