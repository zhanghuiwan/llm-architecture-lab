# 01 语言模型在学什么

本章从一个能在 CPU 上完整训练的小模型开始。它只有一张“当前字符 → 下一个字符”的分数表，却已经具备语言模型训练最重要的接口：离散输入、错开一位的标签、词表上的概率分布、交叉熵，以及逐个 token 生成的循环。先把这些接口理解准确，下一章加入注意力时，才不会把张量错误与模型能力混在一起。

这里的模型是字符 bigram，不是 Transformer，也不是聊天模型。它能学习小语料中相邻字符的统计规律，不能理解长距离关系。我们会实际训练、计算指标和采样，同时观察它明确做不到的事情。

## 学习目标与先修知识

读完本章，你应当能够从原始字符串写出输入和标签，解释 logits、概率和预测类别的区别，说明交叉熵为什么可以作为训练目标，并独立处理不同长度样本的 loss。更重要的是，能够判断一个“损失下降了”的结果究竟支持什么结论。

需要的准备很少：知道整数索引、二维张量与梯度的含义，会运行 Python 脚本。如果广播或 `backward()` 仍不熟悉，可以先阅读[第 00 章](./00-preparation.md)。本章实验使用 PyTorch CPU，不需要 GPU、网络下载、外部文本文件或其他章节的代码。

## 1. 从文本到离散序列

语言模型的输入通常不是字符串本身，而是 token ID。token 可以是字符、字节或子词。不同切分方法会改变序列长度、词表大小和统计单位，因此比较模型时，不能忽略 tokenizer 的差异。

为了把训练目标看清楚，本章采用字符词表。假设“春”“天”“来”“了”“。”分别有整数 ID，再加入三个特殊标记：

| 标记 | 本章 ID | 用途 |
| --- | --- | --- |
| PAD | 0 | 把不同长度输入补成矩形张量 |
| BOS | 1 | 表示句子开始，提供第一个预测位置 |
| EOS | 2 | 表示句子结束，是模型需要学习预测的 token |

真实字符从 ID 3 开始。ID 是类别编号，不表示语义距离。“春”的编号比“冬”小，不代表春天更接近零；模型通过参数学习各个 ID 的统计关系。

例如，一句话会被编码成：

```text
[BOS, 春, 天, 来, 了, 。, EOS]
```

本章的词表只由训练句子中的字符构造，验证句子使用同一个词表；代码检查验证字符全部已知。真实项目必须明确未知字符或未知片段的处理规则，而不是在评估时悄悄扩展词表并改变模型输出层。后面的 tokenizer 章节会进一步讨论字节编码与子词切分。

BOS 和 EOS 的职责不同。BOS 通常放在输入中，让模型预测句首字符；EOS 放在目标中，让模型学习何时停止。如果只在显示结果时截断字符串，却没有训练 EOS，模型本身并没有学会“句子已经结束”。

## 2. 自回归概率与下一 token 预测

对序列 $x_1,\ldots,x_T$，概率的链式法则给出：

$$
p(x_1,\ldots,x_T)=\prod_{t=1}^{T}p(x_t\mid x_{<t}).
$$

链式法则本身不要求使用神经网络。语言模型需要做的是为每个历史提供一个可计算的条件分布。自回归模型从左向右预测：给定已经出现的 token，预测下一个 token；选择一个结果后将它追加到历史，再继续预测。

本章的 bigram 模型进一步限制条件范围：

$$
p_\theta(x_t\mid x_{<t})=p_\theta(x_t\mid x_{t-1}).
$$

它只看紧挨着的前一个 token。“春天”与“冬天”的末尾都是“天”，所以在这两种历史之后，模型输出的下一 token 分布完全相同。即使训练更多轮，这种限制也不会消失，因为模型接口没有接收更早的历史。

这里可以区分两个概念：训练不足是参数还没有找到合适值；结构限制是任何参数都不能表达某类关系。实验会直接比较两段不同历史在相同末尾字符处的输出，验证这个结构限制。下一章的注意力将让当前位置有机会读取更多历史。

为了避免下标混乱，也可以把模型输出理解为“读完当前 token 后预测下一个 token”。同一件事有两种常见记号：用位置 $t$ 的输出预测 $x_{t+1}$，或把目标重命名为 $y_t=x_{t+1}$。只要输入、标签和访问范围一致，两种记号没有本质区别。

## 3. 输入与标签为什么要错开一位

从完整句子构造训练数据时，输入去掉最后一个 token，标签去掉第一个 token：

```text
完整： [BOS, 春, 天, 来, 了, 。, EOS]
输入： [BOS, 春, 天, 来, 了, 。]
标签： [春,  天, 来, 了, 。, EOS]
位置：   0    1   2   3   4   5
```

位置 0 读 BOS，预测“春”；位置 1 读“春”，预测“天”；最后一个位置读句号，预测 EOS。注意训练张量的形状：输入与标签都是 `[B, T]`，但相同位置的 token 含义相差一步。

一个常见错误是直接复制输入作为标签。这样模型学到的是“看见春就输出春”，而不是根据历史预测未来。对于本章的查表模型，这种错误目标甚至很容易得到很低的损失，表面上训练十分成功，却没有完成语言建模任务。

实验在训练前检查每一条样本的输入等于原始编码的 `[:-1]`，标签等于 `[1:]`，并检查 BOS 不出现在有效标签中、每条训练句子恰好贡献一个 EOS 目标。这些检查比只观察最终 loss 更早发现数据对齐问题。

训练通常采用 teacher forcing：预测每个位置时，输入历史来自真实文本。生成时，历史中逐渐包含模型自己的输出。训练过程中所有位置可以并行计算，不代表模型被允许读取未来；对于后续 Transformer，因果 mask 会约束注意力的访问范围。本章每个输出只查当前输入对应的一行参数，本身不存在跨位置读取，因此不需要额外的因果注意力 mask。

## 4. 一张分数表也能成为语言模型

设词表大小为 $V$，模型参数为 $W\in\mathbb{R}^{V\times V}$。输入 ID 为 $i$ 时，取第 $i$ 行：

$$
z=W_{i,:},\qquad z\in\mathbb{R}^{V}.
$$

这行向量称为 logits，是对全部候选下一 token 的未归一化分数。使用 `nn.Embedding(V, V)` 可以实现这张表：

```python
class Bigram(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.table = nn.Embedding(vocab_size, vocab_size)

    def forward(self, tokens):
        return self.table(tokens)
```

输入 `[B, T]`，输出 `[B, T, V]`。在较大的语言模型中，内部隐藏状态通常为 `[B, T, D]`，再通过 LM Head 映射到 `[B, T, V]`。本章跳过隐藏状态，直接查出词表分数，便于隔离训练目标。

Embedding 在这里不是单纯的“词向量表”。它的输出维度恰好为 $V$，直接承担分类器分数表的职责。参数数量为 $V^2$，每个有效输入只更新其对应的行。输入为 PAD 的位置虽然也能产生 logits，但只要对应标签被忽略，就不会因这些位置产生训练梯度。

需要概率时，对最后一维做 softmax：

$$
p_j=\frac{\exp(z_j)}{\sum_{k=1}^{V}\exp(z_k)}.
$$

softmax 不改变 argmax，因此选最大分数与选最大概率得到相同类别。但概率分布可以用来计算不确定性、采样与负对数似然，不能只用 argmax 代替。两个模型即使预测类别相同，对正确答案的置信程度也可能不同，从而产生不同交叉熵。

## 5. 交叉熵：把正确 token 的概率变大

对一个目标类别 $y$，负对数似然为：

$$
\ell(z,y)=-\log\operatorname{softmax}(z)_y
=-z_y+\log\sum_j\exp(z_j).
$$

目标概率接近 1 时损失接近 0；目标概率很小时损失较大。使用自然对数时，单位为 nat。实现时，通常直接把 logits 传给 `cross_entropy`，由稳定的 log-softmax 运算完成归一化：

```python
loss = F.cross_entropy(
    logits.reshape(-1, logits.size(-1)),
    labels.reshape(-1),
    ignore_index=-100,
)
```

不要在这段代码前再加一次 `softmax`。PyTorch 的交叉熵把输入当作 logits；如果传入概率，它会再次进行内部归一化，优化的目标就改变了。也不要简单写 `torch.log(torch.softmax(...))` 来替代稳定实现：当某些概率下溢为零时，直接取对数会产生无穷值。

实验用另一条路径验证交叉熵：先 `log_softmax`，只选择有效位置，再用标签索引取出目标 log-probability，求负均值。两种实现应在浮点容差内一致。

还有一个有用的量级检查。若所有 logits 都相同，则每类概率为 $1/V$：

$$
\ell=-\log(1/V)=\log V.
$$

这严格适用于均匀分布。随机初始化的网络只是可能接近这个量级，不保证精确等于 $\log V$。本章分别报告严格均匀 logits 的损失和随机初始化模型的实际损失，避免把理论参考值当成每次初始化必须满足的等式。

## 6. Padding、mask 与正确的平均方式

不同句长通常需要补齐。本章把较短句子的输入补 PAD，对应标签设为 `-100`：

```text
输入 A： [BOS, 春, 天, 来, 了, 。]
标签 A： [春,  天, 来, 了, 。, EOS]
输入 B： [BOS, 读, 书, 。, PAD, PAD]
标签 B： [读,  书, 。, EOS, -100, -100]
```

`-100` 不是词表 ID，而是 loss 函数约定的忽略值。它不能作为正常索引去访问输出类别，所以手写目标概率提取时必须先筛掉这些位置。模型输入仍必须是合法 ID，不能直接把输入中的 padding 也改成 `-100` 再传入 Embedding。

三个容易混淆的概念应分开：

| 机制 | 控制什么 | 本章是否使用 |
| --- | --- | --- |
| 因果 mask | 当前位置能否读取未来位置 | bigram 不跨位置读取，因此无需额外 mask |
| padding attention mask | 注意力是否访问补齐位置 | 本章没有注意力 |
| loss mask | 哪些目标参与损失与梯度 | 用标签 `-100` 实现 |

忽略 padding 的 loss 并不自动解决 Transformer 的注意力访问问题；反过来，注意力看不到 padding 也不表示这些位置的目标会自动从 loss 中消失。

设有效位置集合为 $\mathcal{M}$，本章的损失为每个有效 token 等权的平均：

$$
L=\frac{\sum_{(b,t)\in\mathcal{M}}\ell_{b,t}}{|\mathcal{M}|}.
$$

如果把一个 batch 拆成多个 microbatch，各自有效 token 数不同，不能简单平均各自的 mean loss。例如一个 microbatch 只有 1 个有效 token，平均 loss 为 4；另一个有 9 个有效 token，平均 loss 为 1。正确结果为 $(4+9)/10=1.3$，直接平均则是 $2.5$。两者代表不同权重，后者让短 microbatch 中的 token 获得了更大影响。

实验将完整 batch 分成大小不同的两部分，用各部分 `reduction="sum"` 累加，再除以全体有效 token 数，检查结果与完整 batch 一致。这个原理同样适用于跨 batch 汇总验证集 loss，以及后面讨论的梯度累积。若每句话等权才是你的研究目标，也可以另行设计权重，但必须明确说明，不能把两种目标混用。

实验还验证两个更直接的性质：改动被忽略位置的 logits 不改变 loss；这些位置的 logits 梯度全部为零。注意这里检查的是 logits 的梯度，不能推断共享模型参数在整个 batch 中都不会更新，因为同一参数可能还服务其他有效位置。

## 7. 损失、困惑度与“学会了”的边界

平均负对数似然 $L$ 的指数是困惑度：

$$
\operatorname{PPL}=\exp(L).
$$

它可以粗略理解为模型对下一 token 有多少等概率候选的不确定程度。对严格均匀的 $V$ 类预测，困惑度为 $V$。计算困惑度时应先把有效 token 的负对数似然正确汇总，再取指数，而不是把每个 batch 的困惑度简单平均。

困惑度只在统计口径一致时有可比性。字符模型和子词模型预测的单位不同，单看数值大小不能判断哪个模型更好。EOS、特殊标记、文档边界、截断长度、是否忽略部分目标，都会改变评估口径。训练集困惑度也不能替代独立数据上的结果。

本章还有一个能精确计算的参照：训练语料的经验 bigram 分布。设 $c_{ij}$ 表示输入 token $i$ 后面接 token $j$ 的次数，最优的无约束行分布为：

$$
\hat p(j\mid i)=\frac{c_{ij}}{\sum_kc_{ik}}.
$$

把这组分布代入训练集负对数似然，得到本章模型在这份数据上的经验下界。训练不必把 loss 降到零，因为同一个输入可能对应多个正确下一 token。例如“天”后面可能接“来”“风”“花”等字符。模型只看当前字符，无法知道它此前属于哪一句。

代码用计数表计算这个下界，并检查训练后的 loss 接近但不低于下界。有限 logits 的 softmax 会给未出现的候选保留极小的正概率，所以数值训练通常只是逼近最优分布。这里的下界针对本章的模型类别和训练语料，不是 Transformer 的损失下界，更不是自然语言预测的普遍极限。

## 8. 独立实验：训练字符 bigram

完整实现位于 [experiments/01-language-modeling/main.py](https://github.com/zhanghuiwan/llm-architecture-lab/blob/main/experiments/01-language-modeling/main.py)。安装方法见[运行实验](../labs.md)。脚本内置 13 条训练句子和 3 条验证句子，词表只从训练文本创建；训练与验证的完整字符串互不相同。这个划分用于演示数据边界，语料非常小且人为构造，不能支持自然语言泛化能力的结论。

在仓库根目录运行：

```bash
python experiments/01-language-modeling/main.py --quick
python experiments/01-language-modeling/main.py --seed 42 --output experiment-results/01.json
python experiments/01-language-modeling/main.py --quick --seed 7
```

这里的 `python` 应指向已安装本项目 CPU 依赖的解释器。脚本只使用 Python 标准库与 PyTorch；`--output` 可选，不提供就不会写入结果文件。所有数据和代码逻辑在同一个文件中，因此也可以从其他工作目录用脚本的绝对路径运行。

`--quick` 运行 80 次全 batch 参数更新，常规模式运行 240 次；两者都执行全部检查。优化器为 Adam，学习率 0.2，分数表采用 FP64，方便比较等价计算的数值误差。这个学习率适用于当前小查表模型，不能直接迁移到 Transformer 预训练。

脚本按下列顺序执行：先构造固定词表和矩形 batch；检查标签位移与 EOS；检查交叉熵、忽略位置和 token 权重；统计经验 bigram 下界；最后训练并生成一个样本。检查使用实际断言，任何失败都会非零退出，不能把“脚本打印了一段文本”当作实验通过。

标准输出是一个 JSON 对象，包含 `chapter`、`seed`、`checks` 和 `metrics`。`checks` 保存各项布尔结果，`metrics` 保存实际 loss、困惑度、分数表词表大小、损失历史和生成文本。输出不夹杂训练进度条，便于后续整书运行器汇总；保存的 JSON 与标准输出表示同一个结果。

解读结果时，先看 `checks` 是否全部为真，再看 `initial_train_loss` 和 `final_train_loss`，最后比较 `empirical_train_bigram_floor`。`validation_loss` 只是另一组句子的观测指标，脚本没有断言它必须优于训练前，也没有把验证文本用于反向传播或模型选择。改变随机种子后，数值和采样文本允许变化，数据对齐与数学等价检查仍应通过。

本章代码在 Python 3.12、PyTorch 2.8.0+cpu 的 CPU 环境实际执行过以下配置。词表大小为 25，训练集包含 76 个有效预测目标；经验 bigram 最优训练损失为 0.585157。表中 loss 使用自然对数，数值仅用于解释这份固定微型数据。

| 模式 | seed | 更新次数 | 初始训练 loss | 最终训练 loss | 验证 loss | 检查 |
| --- | --- | --- | --- | --- | --- | --- |
| quick | 42 | 80 | 3.219163 | 0.588157 | 0.675347 | 19 项通过 |
| 常规 | 42 | 240 | 3.219163 | 0.586500 | 0.674413 | 19 项通过 |
| quick | 7 | 80 | 3.212527 | 0.588155 | 0.675338 | 19 项通过 |

常规模式更接近经验下界，但这个改进非常小，并不证明长文本生成能力提高。quick、seed 42 的固定采样结果是“春天来了。”；seed 7 得到“春天读书。”。这两个文本都是相邻字符规律能够拼出的结果，不能据此推断模型理解季节或阅读。不同 PyTorch 版本下的末位浮点数或随机采样可能变化，应以本机 JSON 为准。

## 9. 生成、温度与可重复性

训练时一次提供整条真实句子；生成时只知道已经产生的 token。每次读取最后一个 token 对应的 logits，形成分布，再选择一个下一 token。预测到 EOS 时停止，否则把新 token 追加到历史，直到达到最大长度。

Greedy 生成每次选择最大 logit。它没有随机抽样，但可能陷入重复，因为一个局部最优选择不保证整句合理。本章使用温度采样：

$$
p_T(j)=\operatorname{softmax}(z/T)_j,\qquad T>0.
$$

温度较低时分布通常更尖锐，温度较高时更平坦。温度不为模型增加知识，也不会扩大 bigram 的上下文范围。它只改变已有分数的归一化方式。实验比较同一组非恒定 logits 在温度 0.6 与 1.6 下的熵，验证高温分布更不确定。

PAD 和 BOS 在生成阶段被设为负无穷分数，避免把补齐符号或句首标记采样进句子。EOS 仍可采样，是正常结束信号。训练 loss 中的概率分布覆盖整个词表，生成时排除不可输出标记属于解码规则，二者需要在报告中分别说明。

为避免训练耗掉随机数后影响样本复现，生成函数创建独立的 `torch.Generator`。同一模型、prompt、温度、最大长度、运行环境与采样种子下，两次生成应一致。实验确实执行两次并比较 token ID，不能只比较人眼看到的字符串。

脚本固定 prompt 为“春”，最大生成 24 个 token。你可能得到语料中的片段，也可能得到奇怪组合。一个看起来通顺的样本不代表理解语言，一个奇怪样本也不意味着交叉熵实现错误。应先用可定位的数学检查确认实现，再根据模型范围讨论生成现象。

## 10. 数据泄漏与常见错误

训练句子与验证句子字符串不同，只是最基础的边界。本章数据高度相似，字符和局部模式大量重叠；它不能代表独立来源的测试集。真实实验还需要检查重复段落、相同文档被切成不同片段、验证集被用于训练或反复调参，以及 prompt 中是否包含答案。

通常应先按文档或来源划分数据，再在各划分内部切成训练窗口。若先把全文切成高度重叠的窗口，再随机分配 train 和 validation，几乎相同的上下文可能同时进入两边。此时验证 loss 很低，主要说明窗口重复，而不是模型能处理新文档。

还应避免以下几类实现错误：

- 把标签直接设为输入，训练成复制器；检查真实原始序列的位移关系。
- 对类别 ID 先做浮点归一化；类别编号应保持整数索引，不能当连续特征处理。
- 把 `[B,T,V]` 直接交给默认按第 1 维解释类别的接口；本章先展平为 `[B*T,V]`。
- 先 softmax 再 cross-entropy；直接传 logits，并用 log-softmax 路径交叉检查。
- 用总位置数除 loss，却没有剔除 padding；应使用实际有效目标数。
- 为了得到更好样本不断换 seed，却只展示最好的一次；应固定规则并记录全部约定。

如果 loss 没下降，先检查目标对齐、有效 token 数、梯度是否存在、参数是否进入优化器以及优化步骤是否执行，再考虑增加层数。模型再大，也不能修复错误的监督目标。

## 11. 练习与提示

1. 在纸上为“今天读书。”写出含 BOS/EOS 的完整序列和全部训练位置。提示：EOS 是目标，BOS 是输入；不要遗漏句号之后的预测。
2. 把某一位置的目标类别概率从 0.1 改为 0.5，计算负对数似然如何变化。提示：使用自然对数，先比较单位置损失，再考虑平均。
3. 将输入复制为标签，观察训练 loss 是否仍然下降。提示：复制模型也能快速学习；请另存实验，不要删除原有 shift 检查来制造“全部通过”。
4. 为验证集分两批，分别计算平均 loss，再实现正确的 token 权重汇总。提示：先累加 loss 总和和有效 token 总数，最后只做一次除法与指数。
5. 用计数表查出“天”之后的经验分布，与模型 softmax 输出比较。提示：比较概率而不是只看 argmax；没有出现的转移在有限 logits 下仍有很小概率。
6. 改用 greedy 生成，并固定同一 prompt 对照温度采样。提示：记录解码规则和最大长度，不给单个文本样本赋予统计显著性。
7. 思考为什么“春天”与“冬天”后面的分布完全相同。提示：直接查看 `forward` 中使用了哪些输入；问题不在训练轮数，而在可访问的历史范围。

能够独立解释上述实验的每个检查，就已经掌握后续模型共享的语言建模接口。下一章会保留 `[B,T] → [B,T,V]` 的训练目标，重点改变中间位置如何读取历史，构建[因果多头注意力](./02-attention.md)。
