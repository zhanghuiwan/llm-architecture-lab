# 05 Tokenizer 与数据管线

Tokenizer 决定模型看到的基本单位。它不仅影响词表，还影响序列长度、计算预算和损失的解释。

## 从字符到 BPE

字符词表易于理解，但文本往往需要更多 Token；字节编码可以覆盖任意字节序列；BPE 通过学习合并规则把常见片段组织为更长单位。更大的词表会增加 Embedding／输出头参数与相关计算，也可能缩短序列，两者需要一起考虑。

实现教学版 BPE 时，逐步完成：统计相邻对 → 选择合并 → 更新序列 → 保存规则。在处理真实 Unicode 文本、特殊 Token 与预切分时，采用成熟实现并固定版本，不把极简算法等同于生产级 Tokenizer。

## 编码与解码的检查

- 普通文本在既定规范下往返一致；若做了归一化，明确说明例外。
- 中文、英文、空白、换行、emoji 与未知输入的行为清楚。
- 特殊 Token 的 ID 与模型配置一致。
- 验证集不会参与 Tokenizer 的训练或选择。

## 文档边界、EOS 与样本拼接

多个文档拼接成训练块时，EOS 告诉模型一段文本结束，但并不自动阻断跨文档 attention。若实验要求文档间隔离，需要对应的 attention mask；若允许跨文档读取，则在配方中明确这一选择。

动态 padding 需要关注位置编号、attention mask 与 loss mask 的一致性。改变拼接方式可能改变有效上下文分布，应视为数据配方变化。

## 不直接比较不同 Tokenizer 的 loss

每 Token loss 的统计单位随 Tokenizer 改变。A 的 Token 数更少，不代表它在同一文本上的建模一定更好。跨 Tokenizer 比较需要统一文本单位和评测协议，例如合适条件下使用按字节归一化的指标。

正式架构对照开始后固定 Tokenizer、数据版本与预处理。字符模型阶段与 BPE 阶段是不同基线，不把二者损失差异归因于网络结构。

## 验收标准

能解释词表与序列长度的权衡，检查特殊 Token 和文档边界，并产出一份固定的数据管线配置。
