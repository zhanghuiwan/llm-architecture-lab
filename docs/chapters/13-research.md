# 13 独立架构实验：从假设到有边界的结论

理解一个组件的公式，和判断它是否值得采用，是两种不同的工作。前面各章建立了数值、因果性、缓存与实现效率的检查方法；本章把这些方法串成一个能够由其他开发者重跑的研究流程。最终产物不是“加入所有新模块”的模型，而是一份问题清楚、预算明确、原始结果完整、结论不过界的实验报告。

本章提供真实执行训练的独立 CPU 实验：比较同一个微型语言模型使用 MHA 和 GQA 时，在相同训练 Token 预算下的表现。它不下载数据、权重或其他章节代码，使用程序内定义的中文字符和合成文档。我们会同时报告理论缓存预算与验证损失，但不预设 GQA 必须更好，也不将几十步训练包装成大模型能力评测。

## 学习目标与先修关系

阅读本章前，应掌握第 01 章的标签位移与交叉熵、第 03—04 章的模型和训练基线、第 07 章的头分组，以及第 09 章的测量边界。代码本身可以单独运行；这些先修关系帮助你理解为什么要控制某些变量，而不是要求先生成其他实验的文件。

完成本章后，你应能把一个宽泛想法改成可被数据推翻的问题，选择一个主要预算并承认其余差异，使用多个配对种子保存原始训练记录，解释均值、样本标准差与配对差，并写出适用范围清楚的结论。另一个重要目标是识别“没有观察到稳定收益”何时是合理结果，而不是急于更换指标寻找一个好看的数字。

## 1. 把研究问题写成可检验的句子

“GQA 比 MHA 好吗”没有规定模型、数据、长度、指标或资源，很难得到可复现的回答。将它改写为：

> 在本章固定的单层、宽度 32、4 个 Query 头的字符模型中，将 KV 头从 4 个改为 2 个，保持相同文档、批次、优化器和每次训练的有效 Token 数，验证交叉熵如何变化？参数和理论 FP32 KV 缓存预算如何变化？

这句话包含两类结论。投影参数与理论 KV 字节数可以由配置直接推导，再与代码统计核对；验证交叉熵的变化必须真正训练和测量。不要把可推导的资源减少，当作尚未测得的语言能力或解码速度收益。

本实验的主要变量是 KV 头数 $H_{kv}$。固定 $H_q=4$、模型宽度 $D=32$、头维度 $d_h=8$，于是 MHA 的 $H_{kv}=4$，GQA 的 $H_{kv}=2$。GQA 头 0 服务 Query 头 0、1，GQA 头 1 服务 Query 头 2、3。代码沿头轴 `repeat_interleave` 展开后调用同一个 SDPA 接口，避免同时引入不同的注意力内核。

这个选择便于检查语义，却不构成最高效的 GQA 内核。展开的 K/V 仍可能占用额外工作内存；本章不依据这个实现宣称实际内存峰值减半。生产推理可用原生分组内核，但更换实现后要重新通过数值和测量检查。

## 2. 选定主要预算，不追求一句话里的“完全公平”

本章采用相同有效训练 Token 数作为主预算。每个批次 $B=8$，每个样本有 $T=12$ 个预测目标，不含 padding，每个优化步骤恰好使用 $BT=96$ 个目标 Token。若训练 $S$ 步：

$$
N_{\mathrm{train}}=SBT.
$$

快速模式每个方案训练 50 步，即每个种子、每个方案 4800 个有效训练 Token；常规模式训练 100 步，即 9600 个。快速模式运行两个配对种子，因此总共执行四次训练；常规模式运行四个配对种子，因此总共执行八次训练。不要把全部运行合计的 Token 数误写成一个方案的预算。

同 Token 不等于同参数、同 FLOPs 或同墙钟时长。GQA 的 K/V 投影更小，正是我们需要记录的结构变化之一。如果改成等参数实验，就必须明确增加了哪个宽度或层数，这时已经是另一个问题。如果改成固定 10 秒训练，就要记录两者实际看过多少 Token，并处理测量噪声和数据管线差异。

实验前应先决定主要约束，运行后再解释结果。根据结果临时从“同 Token”切换成“同时间”，却只公开有利的一种口径，会使读者无法判断真正比较了什么。完整记录见[统一实验规范](/experiments)。

## 3. 固定数据管线，并说明“固定”的含义

实验使用 13 个显式声明的字符：`春夏秋冬山川日月风雨天地。`。这是程序预先定义的封闭字母表，不是拿验证集拟合出来的 BPE。字符到 ID 的映射由字符串位置确定，训练和验证使用同一个映射。

训练文档由“春风。夏雨。秋月。冬日。”等四种模板重复构成；验证文档采用“春日。夏风。秋雨。冬月。”等新的组合。训练与验证文档字符串不相同，但共享字符和短语规律，因此这里只能称为固定合成任务上的留出组合，不能称为独立自然语言分布。简单比较文档集合不相交，也不能证明没有语义泄漏或重复模式。

代码分别在每一篇文档内部构造长度 12 的滑动窗口：

```python
x = ids[offset:offset + length]
y = ids[offset + 1:offset + length + 1]
```

`x` 的每个位置预测文档里的下一个字符。窗口不跨文档拼接，因此不会意外学习训练文档 A 的最后一个字符预测文档 B 的第一个字符。每篇训练文档产生 36 个窗口，共 144 个；两篇验证文档各产生 24 个窗口，共 48 个。重复窗口与重叠目标是教学数据的组成部分，不是数百份独立样本。

验证指标对全部 48 个窗口计算 token 平均交叉熵。因为窗口有重叠，靠近文档内部的位置可能被多次计入。两方案采用完全相同的口径，所以可以做本次对照；报告中仍应说明这不是按原始文档每个 Token 只计一次的评价。

## 4. 预生成批次，核对实际消费的内容

仅把两个模型的 `seed` 设成一样，不保证它们训练时看到相同批次。模型初始化可能消耗不同数量的随机数，dropout、数据增强或额外诊断也会改变后续随机流。本章将数据采样随机流与模型初始化分开：

```python
generator = torch.Generator().manual_seed(pair_seed + 7001)
indices = torch.randint(len(xtrain), (steps, batch_size), generator=generator)
batches = [(xtrain[index], ytrain[index]) for index in indices]
```

同一个配对中的两方案直接使用同一份预生成批次列表，避免把模型结构变化与样本顺序变化混在一起。每次训练还对实际消费的 `x,y` 内容计算 SHA-256，与计划批次的摘要核对；报告同时记录计划值和实际值。它们不依赖 Python 的进程随机 `hash()`。

这里的序列化利用了 Token ID 小于 256 的事实，将扁平 ID 转成 `bytes`。这不是通用张量归档格式：扩展到大词表后应使用包含 dtype、shape 和字节序的规范序列化，不能直接沿用 `bytes(list_of_ids)`。批次摘要一致也只证明本次输入内容及顺序一致，不证明所有训练状态或硬件执行都相同。

训练循环通过累加每个 `y.numel()` 记录实际有效 Token，再核对它是否等于 $SBT$。在含 padding、梯度累积或动态长度的工程里，应统计损失真正使用的目标数量，而不是用一个平均长度估算预算。

## 5. 完整模型与张量路径

两方案都是一层 pre-norm Decoder-only 模型：字符嵌入加可学习位置表，LayerNorm 后进行因果注意力，残差相加，再由 LayerNorm、GELU FFN、残差和最终 LayerNorm 得到 logits。输出头与字符嵌入共享权重。不使用 dropout、RoPE、缓存、混合精度或学习率调度，目的是将本章的比较集中在 KV 头数。

| 张量或配置 | MHA | GQA |
| --- | --- | --- |
| 输入 Token | `[B,T]` | `[B,T]` |
| 隐藏表示 | `[B,T,32]` | `[B,T,32]` |
| Q | `[B,4,T,8]` | `[B,4,T,8]` |
| 未展开的 K/V | `[B,4,T,8]` | `[B,2,T,8]` |
| FFN 中间维度 | 64 | 64 |
| logits | `[B,T,13]` | `[B,T,13]` |

本章使用 `nn.Linear`，权重存储为 `[out_features,in_features]`。K/V 投影的存储形状分别为 MHA 的 `[32,32]` 和 GQA 的 `[16,32]`。模型不包含投影 bias；LayerNorm 则有 scale 和 bias。位置表只包含 12 个位置，训练与验证都使用不超过 12 的窗口；不要把它直接用来验证更长上下文外推。

输出头共享后的唯一参数数量为：

$$
P_{\mathrm{MHA}}=13\times32+12\times32
+3\times2\times32+4\times32^2+2\times32\times64=9184.
$$

GQA 只减少 K、V 投影，每个少 $16\times32$ 个参数，因此减少 $1024$，总参数为 $8160$。输出头与输入嵌入绑定后不能再次重复计数；使用 `model.parameters()` 的去重结果核对理论值。

## 6. 配对初始化：控制共同部分，公开无法相同的部分

如果两方案分别调用默认初始化，即使使用同一个随机种子，形状变化也可能让后续共同参数拿到不同的随机数。这样一次比较包含了结构和大量无关初值变化。我们先构造一个 MHA，再构造 GQA，并显式复制同名同形状的所有参数。代码检查这些参数逐值相同，并在报告中列出参数名称。

K/V 权重形状不同，无法直接逐元素相等。这里将 MHA 头 0 和 2 的 K/V 投影复制为 GQA 的两个 KV 头。没有取平均，也没有额外缩放；它是一条公开的确定性映射，保留所选头的初始化尺度。构造 GQA 后的初始函数仍与 MHA 不同，因为 Query 头 1 和 3 改为读取其他头的 KV。

所有线性层和嵌入使用标准差 0.02 的零均值正态初始化，LayerNorm 保留单位 scale 和零 bias。共同参数在两模型之间复制数值，却不共享存储；否则训练一个方案会改动另一个方案，破坏独立优化。每个模型内部的输入嵌入与输出头则有意共享同一个 `Parameter`。

这仍不是唯一合理的 GQA 初始化方式。可以比较分组均值、选头或独立初始化，但必须将它们作为新的初始化实验，而不是运行后只留下表现最好的映射。初始化策略、学习率配方与结构存在交互，本章结论以这里的固定映射为条件。

## 7. 正确性先行，训练不是调试器

脚本在真实训练前后执行可失败的检查：

- 字母表唯一，训练／验证文档集合不重叠，窗口标签确实右移一位，两份数据摘要不同。
- 同名同形状参数初值相同，GQA 的 KV 权重符合公开的选头映射。
- 修改输入后半段，前六个位置的 logits 不变，输出维度符合 `[B,T,V]`。
- 输入嵌入与输出头确实绑定，训练过程每个参数都有有限梯度，更新后参数保持有限。
- 实际批次摘要与计划一致，有效 Token 与优化步数相符，训练探针交叉熵下降。
- 参数差为 1024，理论缓存字节数按 KV 头比例变化。

验证损失更低不是通过条件。某次 GQA 验证损失高于 MHA，应被保留为正常实验结果；若将“新方案必须优于基线”写成断言，会诱使实现者调种子、调预算或删除不利记录。正确性检查回答实现是否符合约定，结构评价回答特定条件下发生了什么，两者不能混用。

本章的检查不能替代第 02、07 章更细的数值与梯度参考对照。若你修改了注意力内核，应重新运行对应机制检查，再回到本章训练，而不是把损失能下降当作新实现完全正确的证据。

## 8. 训练配置与测量范围

每次训练使用 AdamW，学习率 0.008，`betas=(0.9,0.999)`，`eps=1e-8`，weight decay 为 0.01，梯度范数裁剪阈值为 1.0。为了让配置简洁，所有参数采用同一个衰减组，包括归一化和嵌入；这不是推荐的大模型训练配方，但两方案采用同一规则。代码启用确定性算法，使用 CPU、FP32 和单线程。

每个模型先记录初始训练与验证 loss，再执行指定步数，最后对全部窗口重新评价。训练和验证没有 dropout，因此 `train()` 与 `eval()` 不会改变本章网络的数值路径，但仍保留正确的模式切换，方便读者理解完整流程。

报告中的 `training_seconds` 只包围该模型的训练循环，不包含模型构造、批次生成和最终评价。MHA 总是在 GQA 之前运行，两者没有交错、多轮重复的性能实验；因此这些时长适合排查异常，不能用于宣称哪种结构具有可靠速度优势。若要研究延迟，应另行设计第 09 章那样的性能实验。

本章未测峰值内存、CUDA 时间或 FLOPs。理论 FP32 KV payload 的口径是单层、批量 8、长度 12，每元素四字节：

$$
M_{KV}=2BTH_{kv}d_h\times4.
$$

MHA 为 24576 字节，GQA 为 12288 字节，恰好减半。这是将来增量解码缓存所需的理论数据量；当前训练脚本没有实现 KV Cache，也没有据此声称进程实际内存峰值减半。

## 10. 一次实际运行的结果

下面是 CPU、PyTorch 2.8.0+cpu、FP32、单线程、基础种子 42 的实际输出，按六位小数展示。其他平台或版本可能出现数值差异，应以自己的原始 JSON 为准。快速模式共通过 50 项检查：

| 配对种子 | MHA 最终训练 loss | GQA 最终训练 loss | MHA 验证 loss | GQA 验证 loss |
| --- | --- | --- | --- | --- |
| 42 | 0.592640 | 0.576381 | 2.492224 | 2.435540 |
| 143 | 0.744149 | 0.627297 | 2.520937 | 2.496553 |

两个方案的初始训练 loss 约为 2.59—2.60，训练后明显下降，证明该配置能优化这份小数据。验证 loss 仍接近 2.4—2.5，不能由训练 loss 很低推断泛化成功。快速模式两次配对的验证差 `GQA−MHA` 均为负，均值约为 -0.040534；这只是本次两个种子的观测。

常规模式将每次训练扩到 100 步，增加到四个配对，共通过 94 项检查：

| 配对种子 | MHA 验证 loss | GQA 验证 loss | 差值 GQA−MHA |
| --- | --- | --- | --- |
| 42 | 3.323982 | 3.744595 | 0.420613 |
| 143 | 3.588407 | 3.269681 | -0.318726 |
| 244 | 3.688714 | 3.131162 | -0.557552 |
| 345 | 3.230186 | 3.655972 | 0.425786 |

更长训练让训练 loss 继续下降，却让这份留出组合上的验证 loss 变差。四个配对的差值有正有负，均值约 -0.007470，样本标准差约 0.506766。不能根据一个很小的负均值就写“GQA 能力更强”；更合适的结论是：在本任务和配方下，两种结构的验证差随种子与训练阶段明显变化，未形成稳健的优劣判断，参数与理论缓存的减少则符合推导。

基础种子改为 7 后，快速模式的两个配对差值也有不同符号。它进一步说明不能从第一次观察就挑选有利种子。这不是模型缺陷的证明，而是这个小规模实验对结构收益的辨识能力有限。

## 11. 配对差、样本标准差与标准误

对第 $i$ 个配对，定义：

$$
\Delta_i=L^{GQA}_i-L^{MHA}_i,\qquad
\bar\Delta=\frac{1}{n}\sum_{i=1}^{n}\Delta_i.
$$

loss 越低越好，因此负差值表示该配对中 GQA 更低。配对差保留“相同初始化共同部分与相同批次”的对应关系，不能先分别挑选两个方案各自最好的种子再做差。即使两个方案的平均 loss 相近，配对差的离散程度仍可能很大。

脚本使用分母 $n-1$ 的样本标准差：

$$
s_\Delta=\sqrt{\frac{1}{n-1}\sum_i(\Delta_i-\bar\Delta)^2},
\qquad SE=\frac{s_\Delta}{\sqrt{n}}.
$$

`statistics.stdev` 对应样本标准差，不是分母为 $n$ 的总体标准差。本章还记录各方案验证 loss 的样本标准差，但不能把“两个各自标准差相加”当作配对差的标准差。

这里的标准误只描述将这些种子视为重复运行时均值波动的一个估计，没有涵盖数据集选择、任务设计、超参数搜索或实现版本的不确定性。快速模式只有两个配对，常规也只有四个；不适合给出强统计推断。脚本没有输出 p 值、显著性判断或正态近似的 95% 区间，也没有声称这些少量种子证明了等效或优越。

## 12. 常见错误与诊断顺序

**先比较模型的参数和计算路径。** 如果参数差不是 1024，检查输出头是否重复统计、K/V 的 `out_features` 是否仍等于 32，或不小心改变了 FFN。不要通过调整其他模块来让参数数字“看起来相近”，那会改变当前研究问题。

**再比较输入摘要和有效 Token。** 两个模型都运行 50 步，不代表看过同样的内容；两份数据集名字相同，也不代表版本相同。若批次摘要不同，优先检查是否共享同一个随机采样器、是否在两个模型之间推进了随机流，以及是否有按模型结果筛选样本的逻辑。

**检查共同参数是否只复制了数值。** 若误把两个模型的同名参数绑定成同一个对象，一个优化器会改动另一个模型。反过来，模型内部输入输出权重的绑定又是有意设计，不能为了方便统计而拆开。共同初始化与共同存储是不同概念。

**检查最终评价是否真正使用同一批验证样本。** 随机抽一批验证数据就比较，可能让样本噪声超过结构差异。本章对全部固定窗口评价，但也如实承认重复窗口和模板数据的局限。

**遇到训练 loss 下降、验证变差时，不要隐藏后半段。** 这可能是过拟合、训练／验证组合变化或配方问题。增加训练步数并不保证更好的验证表现。若要使用早停或选择最佳检查点，应预先固定选择规则，并保留独立测试集，不能用同一验证集无限调参后再宣称泛化收益。

## 14. 练习与提示

1. **改变预算，而不改变问题描述。** 先写一份等参数实验方案，再找出它与本章等 Token 问题的不同之处。提示：补偿 K/V 参数差时，应明确改变的是 FFN 宽度、隐藏维度还是其他组件，并重新计算所有参数。
2. **比较初始化映射。** 将选头改为分组均值，记录是否需要尺度处理，并在固定批次下重复多种子实验。提示：这是结构与初始化的交互研究，不要只挑一个更好看的映射替代原记录。
3. **增加一个完全独立的测试划分。** 提出新的合成组合或许可明确的文本数据方案，说明验证集用于哪些选择，测试集在何时使用。提示：重复模板的随机切片不等于独立文档划分。
4. **做调参预算对称的比较。** 为两个结构定义相同数量的学习率候选和运行种子，再比较各自最优配置。提示：固定配方直接替换与对称调参回答不同问题，两种结果都应保留条件说明。
5. **从 JSON 重算统计。** 不调用脚本内部函数，读取 `pairs` 的原始 loss 重算均值、样本标准差与标准误。提示：先按配对计算差，再计算差的离散程度；保留未舍入值。
6. **设计真正的解码测量。** 在通过第 08 章缓存一致性检查的基础上测量 MHA/GQA。提示：固定 batch、prefill 长度、生成长度、dtype 和内核，预热与同步后报告分布，不拿本章训练循环时长代替 decode 延迟。
