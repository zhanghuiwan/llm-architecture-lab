# 07 MHA、MQA 与 GQA

这些结构改变 Query 与 Key/Value 头的对应关系。先画清头的分组，再推导缓存与参数预算。

## 三种头组织

| 结构 | KV 头数 | 组织方式 |
| --- | --- | --- |
| MHA | $H_{kv}=H_q$ | 每个 Query 头对应自己的 KV 头 |
| MQA | $H_{kv}=1$ | 所有 Query 头共享一组 KV |
| GQA | $1<H_{kv}<H_q$ | 每组 Query 头共享一组 KV |

常见实现要求 $H_q$ 可被 $H_{kv}$ 整除。教学实现可以显式重复 KV 头验证对应关系，高效实现则应避免不必要的实际复制。

## 参数量推导

假设 $D=H_qd_h$，Q 与 O 投影各有约 $D^2$ 参数，K 与 V 投影各有约 $DH_{kv}d_h$ 参数：

$$
P_{attn}\approx 2D^2+2DH_{kv}d_h.
$$

GQA 通常减少 K/V 投影与缓存容量，但减少多少总模型参数，还取决于 FFN、词表及其他模块。

## KV Cache 预算

对标准缓存布局、等维 K/V、批量 $B$、层数 $L$、长度 $T$、每元素 $s$ 字节：

$$
\operatorname{KVBytes}=2BLTH_{kv}d_hs.
$$

例如 $B=1,L=32,H_{kv}=8,d_h=128,s=2$，每 Token 需要 128 KiB。若 $T=262144$，理论 KV 为 32 GiB。这不包括参数、激活、分配器开销、缓存分页元数据或其他系统状态，也不是 MLA 等特殊缓存布局的通用公式。

## 实验设计

先固定 Query 头数、隐藏维度与训练 Token，比较不同 KV 头数。此时参数量会变化，应如实报告；若要比较等参数预算，需要另设计参数补偿实验，并承认它同时改变了其他配置。

## 验收标准

能从模型配置计算投影形状与缓存大小，正确实现 Query/KV 头分组，并避免把缓存减少直接等同于推理加速。
