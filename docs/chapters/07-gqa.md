# 07 MHA、MQA 与 GQA

多头注意力中的“多头”可以指两件不同的事：有多少组 Query，和保存多少组 Key、Value。基础 MHA 把它们设成相同数量，所以容易误以为三个投影必须拥有相同输出维度。本章把这两件事拆开，得到 Multi-Query Attention（MQA）和 Grouped-Query Attention（GQA）。

我们先画清 Query 到 KV 的对应关系，再实现一种不显式重复 KV 的分组计算，最后用独立参考实现和梯度核对它。实验还会统计参数及缓存张量的有效载荷字节数。它不训练模型，也不测推理速度，因此不能用来证明 GQA 比 MHA 能力更强或运行更快。

## 学习目标与先修关系

读完本章，你应能完成四件事：从配置写出 Q/K/V/O 的权重形状；解释每个 Query 头使用哪一个 KV 头；验证两种等价实现的输出和梯度；从缓存布局计算理论字节数，并说明公式没有覆盖什么。

先修是第 02 章的因果多头注意力和第 03 章的残差模型。理解本章计算不要求先实现 KV Cache，第 08 章会把这里的 KV 头维度放入真正的增量解码流程。RoPE 等位置编码也可以作用在分组注意力中，但为了只研究头组织，本章脚本不添加位置编码和其他 Block 组件。

配套代码位于 [experiments/07-gqa/main.py](https://github.com/zhanghuiwan/llm-architecture-lab/blob/main/experiments/07-gqa/main.py)，包含自己的投影、数据与检查，不导入其他章节。安装环境见[运行实验](/labs)。

## 1. 先区分 Query 头与 KV 头

设输入 $X\in\mathbb{R}^{B\times T\times D}$。$B$ 是批量，$T$ 是序列长度，$D$ 是隐藏维度。记 Query 头数为 $H_q$，KV 头数为 $H_{kv}$，每头维度为 $d_h$。本章采用常见的简化条件：

$$
D=H_qd_h,\qquad H_q\bmod H_{kv}=0.
$$

组内 Query 数为 $R=H_q/H_{kv}$。第二个条件使每个 KV 头恰好服务相同数量的 Query 头。这个整除约束来自本章采用的均匀分组实现；它不是关于所有可能注意力结构的数学定理。真实模型还可能允许投影总宽度与隐藏宽度不同，分析那些配置时应回到实际投影形状，不能直接套用 $D=H_qd_h$。

| 结构 | KV 头数 | 对应关系 |
| --- | --- | --- |
| MHA | $H_{kv}=H_q$ | 每个 Query 头拥有自己的 KV 头，$R=1$ |
| MQA | $H_{kv}=1$ | 所有 Query 头共享同一 KV 头，$R=H_q$ |
| GQA | $1<H_{kv}<H_q$ | 每 $R$ 个 Query 头共享一个 KV 头 |

这里的“共享”是 K/V 投影和序列表示的共享，并不是把同一组注意力权重复制给所有 Query 头。Query 投影仍有 $H_q$ 个头；即使两个头看到同一个 K，它们的 Query 一般不同，点积得分与 softmax 权重也就不同。因此 MQA 并没有退化成单头注意力。

### 一个六头例子

令 $H_q=6,H_{kv}=2$，则 $R=3$。本章采用连续分组：

```text
Query 头:  0  1  2 | 3  4  5
KV 头:     0  0  0 | 1  1  1
```

第 $h$ 个 Query 头使用的 KV 索引为 $g(h)=\lfloor h/R\rfloor$。公式中的头顺序必须和张量内存中的头顺序一致。另一种排列也可以形成某种合法模型，但若权重、代码和参考实现没有同步重排，它就不是同一个函数。

这一点在形状检查中发现不了：`[0,0,0,1,1,1]` 和 `[0,1,0,1,0,1]` 都有六个元素，却描述了不同分组。稍后我们将专门加入错误重复顺序的反例。

## 2. 从投影形状推导参数量

本章使用无偏置线性层，并以右乘矩阵表示投影：

$$
W_Q\in\mathbb{R}^{D\times H_qd_h},\quad
W_K,W_V\in\mathbb{R}^{D\times H_{kv}d_h},\quad
W_O\in\mathbb{R}^{H_qd_h\times D}.
$$

注意 PyTorch `nn.Linear` 内部权重按 `[out_features, in_features]` 存放；这里为了直接写 `x @ weight` 采用转置后的记法。比较配置或统计参数时，应区分数学表达和框架存储方向。

投影、拆头后的布局是：

| 张量 | 投影结果 | 本章注意力内部布局 |
| --- | --- | --- |
| Q | `[B,T,Hq*dh]` | `[B,Hq,T,dh]` |
| K | `[B,T,Hkv*dh]` | `[B,Hkv,T,dh]` |
| V | `[B,T,Hkv*dh]` | `[B,Hkv,T,dh]` |
| 每头输出 | — | `[B,Hq,T,dh]` |
| 合头及 O 投影 | `[B,T,Hq*dh]` | `[B,T,D]` |

因为输出仍由全部 Query 头产生，O 投影的输入宽度由 $H_q$ 决定，而不是 $H_{kv}$。把合头输出误设成 `Hkv*dh`，不仅是一次形状疏忽，也改变了模型的残差接口。

将四个矩阵的元素数相加，并代入 $D=H_qd_h$：

$$
P_{attn}=2D^2+2DH_{kv}d_h.
$$

MHA 的结果是 $4D^2$；MQA 则是 $2D^2+2Dd_h$。下降的部分是 K/V 投影，Q 与 O 没变。偏置、位置参数、Norm、FFN 和词表参数均不在这个统计口径里。如果模型使用投影偏置，还要加上 $H_qd_h+2H_{kv}d_h+D$，不能把本章无偏置公式说成整个模型的精确参数量。

减少 KV 头数会同时改变参数量与共享约束，因此“其余超参数相同”的 MHA/GQA 对照并不是等参数实验。用更宽 FFN 补偿参数虽然可行，但它又改变了另一个模块。应先选择主要预算，再明确报告其他差异。

## 3. 不展开 KV 的分组计算

对第 $h$ 个 Query 头和目标位置 $t$，因果注意力可以写成：

$$
s_{h,t,s}=\frac{q_{h,t}^{\mathsf T}k_{g(h),s}}{\sqrt{d_h}},\qquad s\leq t,
$$

$$
a_{h,t,:}=\operatorname{softmax}(s_{h,t,:}),\qquad
z_{h,t}=\sum_{s\leq t}a_{h,t,s}v_{g(h),s}.
$$

缩放仍使用参与点积的 $d_h$，不是隐藏宽度 $D$，也不是 KV 头数。softmax 在 Key 位置 $s$ 上归一化；它不会跨组或跨 Query 头混合概率。

### 显式保留分组维度

将 Q 从 `[B,Hq,T,dh]` 拆成 `[B,Hkv,R,T,dh]`。其中 `g` 是 KV 组，`r` 是组内 Query 编号：

```python
qg = q.reshape(batch, kv_heads, repeats, time, head_dim)
scores = torch.einsum('bgrtd,bgsd->bgrts', qg, k) / head_dim**0.5
probabilities = scores.masked_fill(~allowed, -torch.inf).softmax(-1)
out = torch.einsum('bgrts,bgsd->bgrtd', probabilities, v)
```

K 和 V 保持 `[B,Hkv,T,dh]`。第一个 `einsum` 中，`g` 在两边同时出现，所以 Query 只和自己的 KV 组相乘；`r` 只出现在 Q 中，所以组内不同 Query 共享 K。第二个 `einsum` 在 Key 位置 `s` 上求和，得到每个 Query 头自己的输出。

本章 `allowed` 是 `[T,T]` 的下三角布尔矩阵，`True` 代表允许访问。它广播到 `[B,Hkv,R,T,T]`，保证一个位置可以访问自己与过去。由于每行至少允许当前位置，不会出现整行负无穷导致未定义 softmax 的情况。引入 padding 或其他规则时，必须重新检查全屏蔽行，本章实验没有 padding。

得到 `[B,Hkv,R,T,dh]` 后，把组与组内头合并回 `[B,Hq,T,dh]`，再转置成 `[B,T,Hq,dh]` 合头。`transpose` 后使用 `contiguous().reshape(...)` 或等价的安全操作，避免用错误的 `view` 悄悄假设存储连续。

### 哪些计算没有减少

虽然 K/V 的头数减少，Query 头数仍是 $H_q$。这个教学实现显式物化的得分矩阵仍有 $BH_qT^2$ 个元素，主要 QK/AV 运算仍随 Query 头数增长。它节省 KV 投影与 KV 表示，不代表整段训练的注意力计算和中间激活都按 $H_{kv}/H_q$ 缩小。

脚本的分组 `einsum` 避免显式复制 K/V，但这并不保证底层实现比另一种写法更省峰值内存或更快。是否物化中间值、使用何种 kernel 和硬件带宽都需要额外测量。这里先保证函数语义正确，性能测量留到第 09 章。

## 4. 三条独立的正确性证据

只检查输出 shape 或“没有 NaN”不够。本章采用分组计算、重复 KV 的 SDPA 参考，以及逐 Query 头循环三条路径。

### 参考一：连续重复 KV

```python
kr = k.repeat_interleave(repeats, dim=1)
vr = v.repeat_interleave(repeats, dim=1)
out = F.scaled_dot_product_attention(
    q, kr, vr, is_causal=True, dropout_p=0.0
)
```

这条路径将紧凑的 KV 明确展开到 $H_q$ 个头，再交给 PyTorch SDPA。它不是我们要部署的缓存格式，而是便于验证的参考。即使较新 API 支持原生 GQA，本章也不依赖设备与后端相关的原生 GQA 支持；参考路径只调用普通等头数 SDPA。

本章关闭 dropout，使用 CPU FP64。不同计算顺序仍可能产生舍入误差，因此以容差比较，不要求浮点逐位相等。实验阈值是前向最大绝对误差小于 `1e-10`，梯度采用 `atol=rtol=1e-9` 的对照标准；这不是混合精度训练可直接照搬的容差。

### 参考二：逐头索引

逐头循环直接取 `group = head // repeats`，每头独立执行矩阵乘、因果屏蔽与 softmax，再堆叠输出。这条实现较慢，但不复用分组 `einsum` 的下标表达，也不依赖 KV 展开的排列方式。若两条向量化实现偶然共享同一个映射错误，逐头参考可以提供额外证据。

### 梯度也要一致

前向误差小不等于实现适合训练。例如错误的 `detach` 可能不改变输出，却截断了反向传播。脚本为两条路径创建数值相同、互不共享存储的输入与四个投影矩阵；用随机探针 $U$ 构造标量目标：

$$
\mathcal{L}=\sum_{b,t,d}Z_{b,t,d}U_{b,t,d}.
$$

随后分别对 $X,W_Q,W_K,W_V,W_O$ 求梯度。每一项都检查数值有限、非零且与参考一致。在重复 KV 的参考中，同一个原始 K/V 会被多个 Query 头使用，autograd 会将这些路径的梯度求和回紧凑 KV。分组写法必须得到相同的累加结果。

这验证的是“同一 GQA 函数的两种实现”等价，不是 GQA 与任意 MHA 权重等价。只有在特定共享权重约束下，MHA 才能表示出同样的共享结构。已经独立训练的 MHA 权重不能仅靠改变 `num_key_value_heads` 就无损变成 GQA。

## 5. 用错误重复顺序做反例

对于两个 KV 头、每组三个 Query：

```python
# 正确映射：[0, 0, 0, 1, 1, 1]
k.repeat_interleave(3, dim=1)
# 本章分组约定下的错误映射：[0, 1, 0, 1, 0, 1]
k.repeat(1, 3, 1, 1)
```

两者 shape 相同，通常也都能顺利计算。只有当 $H_{kv}>1$ 且 $R>1$ 时，这个反例才区分两种排列；在 MQA 中只有一个 KV 头，或者 MHA 中重复次数为一，它们恰好相同。所以只在 MHA/MQA 两端做测试，可能漏掉中间 GQA 的映射错误。

脚本只在满足条件的 GQA 配置中运行反例，并要求错误输出与正确输出存在明显差异。这里的“通过反例检查”指成功识别了错误函数，不是允许错误函数参与正式训练。负向对照说明检查具备区分能力，避免写出一个无论怎样排列都返回成功的测试。

此外，脚本修改未来位置的输入，检查过去前缀输出保持不变，同时检查受扰动的末尾输出确实变化。后一个条件防止“模型完全忽略输入，所以因果检查当然通过”的退化情况。

## 6. KV Cache 的字节数应该怎样算

标准自回归推理为每一层缓存历史位置的 K 和 V。若两者头维度相同，缓存为稠密、未量化、未共享前缀的布局，每个元素占 $s$ 字节，则有效载荷为：

$$
\operatorname{KVBytes}=2BLTH_{kv}d_hs.
$$

这里的 $L$ 是层数，前面的 2 代表 K 和 V。对于一个序列，每新增一个 Token，理论增量为 $2LH_{kv}d_hs$ 字节。若以整个批量计，则还要乘 $B$。变长批量、分页预留空间和共享前缀缓存需要按实际存储槽位重新统计。

### 一个较大配置的手算

取 $B=1,L=32,H_{kv}=8,d_h=128,s=2$。每 Token 的缓存为：

$$
2\times32\times8\times128\times2=131072\text{ bytes}=128\text{ KiB}.
$$

长度 $T=262144$ 时，理论缓存为 $34359738368$ 字节，即 32 GiB。这里使用二进制单位，$1\text{ GiB}=2^{30}$ 字节，不能把 GiB 和十进制 GB 混在一张表中。

这是手算预算，不是本章申请了 32 GiB 内存后的实测结果。模型权重、激活、优化器、分配器碎片、临时工作区和缓存分页元数据都未包含。MLA 等采用不同潜变量布局的结构也不应直接套用该公式。

### 实验如何核对公式

代码只分配小型的 K/V 缓存张量，形状为 `[B,L,T,Hkv,dh]`，通过 `numel() * element_size()` 求有效载荷。比较它和公式，可以抓出漏乘层数、批量、K/V 数量或 dtype 字节数的错误。这个统计没有测量操作系统报告的进程内存，更不是峰值显存。

固定 $B,L,T,d_h,s$ 时，缓存相对 MHA 的比例恰为 $H_{kv}/H_q$。但总模型参数的比例不是这个数，因为 Q/O 和模型其他部分没有跟着变化。

## 7. 运行独立实验并解读真实结果

在已按实验指南建立虚拟环境的仓库根目录执行：

```bash
.venv/bin/python experiments/07-gqa/main.py --quick
.venv/bin/python experiments/07-gqa/main.py
.venv/bin/python experiments/07-gqa/main.py --quick --seed 7
.venv/bin/python experiments/07-gqa/main.py --quick --output experiment-results/gqa.json
```

快速模式使用 $B=2,T=5,D=24,H_q=6,d_h=4$，依次测试 $H_{kv}=1,2,6$；常规模式使用 $B=3,T=7,D=48,H_q=8,d_h=6$，测试 $H_{kv}=1,2,4,8$。特意令 $T\ne d_h$，减少把序列维和头维误交换却恰好不报错的可能。缓存层数设为 4，dtype 为 FP64，每元素 8 字节。

以下是本章在 CPU PyTorch `2.8.0+cpu`、seed 42 下真实运行的快速模式结果，数值误差末位可随环境变化：

| KV 头数 | 对应类型 | 四投影参数数 | 缓存有效载荷 | 相对 MHA 缓存 |
| --- | --- | --- | --- | --- |
| 1 | MQA | 1344 | 2560 字节 | 1/6 |
| 2 | GQA | 1536 | 5120 字节 | 1/3 |
| 6 | MHA | 2304 | 15360 字节 | 1 |

快速模式的 61 项检查全部通过。三种配置中，分组计算与重复参考的最大前向绝对误差约为 $6.66\times10^{-16}$，输入和四个投影矩阵梯度的最大误差约为 $5.11\times10^{-15}$。错误 `repeat` 在中间 GQA 配置产生约 2.04 的最大输出差异，证明该负向对照没有与正确映射偶然重合。

常规模式实际通过 80 项检查，最大前向误差约 $8.88\times10^{-16}$，最大梯度误差约 $1.42\times10^{-14}$。快速 seed 7 也通过 61 项检查。检查项数量随配置数量变化，并不表示常规模式包含更多模型层；它只是多测了一种 GQA 分组。

报告 `metrics.cases` 按 KV 头数列出 `query_to_kv`、参数、字节数、误差和反例差异。`wrong_repeat_max_abs_delta` 在 MQA/MHA 中为 `null`，表示该反例没有区分能力而未运行，不应解释为“错误实现误差为零但仍被判失败”。所有正式执行的检查都在 `checks` 中，任何一项失败会让脚本非零退出。

运行 `--output` 时，保存的 JSON 与标准输出是同一对象；脚本不依赖当前目录，也不生成训练 checkpoint。把输入规模改大之前应先估算得分矩阵的平方增长，不能因为 KV 变小就假定任意长序列都安全。

## 8. 常见错误与定位顺序

遇到前向错误，先打印 `query_to_kv`，再检查 Q/K/V 的各个轴，最后检查合头顺序。若所有 shape 都正确但结果不一致，优先怀疑 `repeat` 与 `repeat_interleave`、softmax 轴或转置顺序。

若前向正确、K/V 梯度不正确，检查是否在展开或缓存逻辑中用了 `detach`、是否重复创建了独立参数，以及共享 KV 的多条梯度是否被正确累加。推理缓存可以脱离训练图，本章训练语义对照却不能悄悄截断梯度。

若因果前缀受到未来扰动，检查三角方向、布尔 mask 语义以及 SDPA 是否误设为非因果。若修改所有输入输出都没变化，检查权重、数据和断言是否构成退化测试，不能仅把前缀“不变”当成成功。

若缓存比例正确而总内存没有等比例下降，应先确认比较的是哪种内存指标。参数、Query 激活、得分矩阵、kernel 工作区和分配器都可能占据主要部分。这种现象并不推翻 KV 有效载荷公式，也不能靠修改公式掩盖真实系统代价。

## 9. 练习与提示

1. **手算参数与缓存。** 令 $D=1024,H_q=16,H_{kv}=4,d_h=64$，计算四投影参数及相对 MHA 的比例；再取 $B=2,L=24,T=4096,s=2$ 计算缓存。提示：参数中 Q/O 固定，缓存中所有项都要保留，先以字节算再转换单位。
2. **改成八个 Query 头。** 把快速模式改为 $D=32,H_q=8$，测试 KV 头数 1、2、4、8。提示：同步修改配置集合；不要修改 `g(h)` 的定义。检查所有分组都有梯度参考与因果检查。
3. **验证共享梯度的来源。** 只保留一组中的一个 Query 头对损失的贡献，分别计算 K 梯度，再把这些贡献相加，与整组损失的梯度比较。提示：线性求和来自同一共享 K 被多条计算路径使用，不是参数被复制后独立更新。
4. **尝试交错分组。** 将目标映射改为 `h % Hkv`，同步修改分组实现、逐头参考和展开方式。提示：一种排列“错误”是相对于具体约定；如果全部路径一致重排，它可以定义另一个有效函数。保持原权重却只改某一条路径，仍应被检查识别。
5. **区分参数与缓存优化。** 写出将 KV 头数减半后，注意力参数、全部模型参数与 KV 缓存分别怎样变化。提示：需要补充 FFN 与词表参数的假设，才能回答整个模型；不要把局部比例扩展为全模型比例。
6. **设计速度实验而不预设答案。** 为分组 `einsum` 和显式重复路径列出同语义、同精度、预热、线程数、计时范围和内存统计口径。提示：本章没有给出它们谁更快；可以将方案带到第 09 章实际测量。
