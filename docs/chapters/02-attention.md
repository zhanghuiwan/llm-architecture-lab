# 02 因果多头注意力

上一章把语言建模写成“根据前缀预测下一个 token”。现在要解决模型内部的一项具体计算：位置 $i$ 应从哪些已有位置读取信息，如何将读取结果组织成向量？本章先把这个问题写成矩阵运算，再验证它的输出、梯度和信息依赖。我们的目标不是背下 Q、K、V 三个字母，而是能够在纸上追踪每个维度，在代码里发现形状正确但含义错误的实现。

本章实验使用随机小张量，不训练模型，不下载数据或权重。它验证一项计算是否符合预期，不证明某个架构的语言能力。完整实现见 [独立实验 main.py](https://github.com/zhanghuiwan/llm-architecture-lab/blob/main/experiments/02-attention/main.py)。只需要 Python 与 CPU 版 PyTorch，既可从仓库运行，也可复制单个脚本到其他目录运行。

## 学习目标与先修知识

读完并完成实验后，你应能解释注意力分数和 Value 聚合的区别，逐步写出从 `[B,T,D]` 到 `[B,H,T,T]` 再回到 `[B,T,D]` 的变换；能够说明 softmax 应沿哪个轴进行，以及因果掩码为什么必须包含对角线；能够使用参考实现比较前向和梯度，并设计一个“即使没有训练数据也能发现读取未来”的检查。

需要的先修知识是矩阵乘法、广播、softmax、自动求导，以及下一 token 预测的标签右移。若 `transpose` 和 `reshape` 的差别还不清楚，先回到第 00 章。本章不要求掌握 Transformer 的残差结构、位置编码或 KV Cache：这些内容后面分别讨论。这里的约定是完整序列、没有 padding、每个头具有相同的维度、Q/K/V 头数相等的标准自注意力。这个范围足以建立可信的参考计算，但不能直接当作所有推理场景的通用实现。

## 从一个位置的加权读取开始

设第 $i$ 个位置有 Query 向量 $q_i$，每个候选位置 $j$ 有 Key 向量 $k_j$ 和 Value 向量 $v_j$。我们用 Query 与 Key 的内积给候选位置打分，再将分数归一化：

$$
s_{ij}=\frac{q_i^\top k_j}{\sqrt{d_h}},\qquad
\alpha_{ij}=\frac{\exp(s_{ij})}{\sum_{r\le i}\exp(s_{ir})}\quad(j\le i).
$$

因果自注意力只允许读取 $j\le i$ 的位置；对于 $j>i$，直接令权重为零。最终输出是 Value 的加权和：

$$
z_i=\sum_{j\le i}\alpha_{ij}v_j.
$$

这里有两个不同的计算。Q 和 K 决定“读谁以及读多少”，V 决定“被读取的内容是什么”。它们都由同一份输入产生，却使用不同的可训练投影。不能因为输入相同就把三组权重绑定，也不能把注意力分数本身当作要传给下一层的内容向量。

做一个不依赖随机数的手算：假设位置 $i=1$ 的两个允许分数恰好都是零，则 softmax 权重为 $[0.5,0.5]$。若两个 Value 为 $[2,0]$ 与 $[0,4]$，输出就是 $[1,2]$。即使后面存在一个分数特别大的候选位置，只要它在未来，因果掩码也必须使它的贡献为零。改变那个未来 Value 不应影响当前输出。这正是后面扰动实验要检测的性质。

注意力权重非负且和为一，因此在给定 V 时，单头聚合位于那些 Value 的凸包内。但整个注意力模块还包含可学习的 Value 投影和输出投影；不要据此推断完整模块只能输出原输入的某种“平均”，更不要将某个高权重直接解读为可靠的自然语言解释。

## 缩放因子的作用与适用前提

假设 Query、Key 的各维分量近似独立，均值为零、方差为一，那么内积是 $d_h$ 项乘积之和，方差大致随 $d_h$ 增长。将内积除以 $\sqrt{d_h}$，可使不同头维度下的初始分数尺度较可控。如果分数差距过大，softmax 容易接近 one-hot，一些方向的梯度随之变小。

这个解释依赖分布假设，并不声称真实网络每一层都满足独立同分布。缩放也不是处理所有溢出问题的保证。低精度、异常激活、错误初始化都可能让计算失稳。后面现代 Block 一章会讨论 QK 归一化等不同设计；目前应先确保标准缩放点积注意力的公式与实现一致。

PyTorch 的 SDPA 在未传入额外 `scale` 时已经使用标准缩放。本章手工实现除一次，SDPA 参考分支由接口完成一次。若先把 Q 除以 $\sqrt{d_h}$，又使用默认 SDPA，就重复缩放了。形状与有限值检查都不一定发现这个错误，数值参考对照才会暴露它。

## 多头：按什么方式组织张量

输入记为 $X\in\mathbb{R}^{B\times T\times D}$，其中 B 是 batch，T 是序列长度，D 是模型宽度。取 H 个头，每头维度 $d_h=D/H$，本章要求 D 能被 H 整除。使用四个不带 bias 的方阵：

$$
W_Q,W_K,W_V,W_O\in\mathbb{R}^{D\times D}.
$$

脚本采用 `x @ w` 约定，所以 `w` 的两个轴分别是输入维与输出维。`torch.nn.Linear` 内部权重通常保存为 `[out_features,in_features]` 并使用转置相乘；抄写两种实现时必须分清约定。此处不使用 bias 是为了让对照更清楚，不代表注意力在定义上不能有 bias。

投影后得到三份 `[B,T,D]`，将最后一维拆成 `[H,d_h]`，再交换序列轴与头轴：

```python
# x: [B, T, D]
projected = x @ w
heads_view = projected.reshape(B, T, H, d_h)
q = heads_view.transpose(1, 2)  # [B, H, T, d_h]
```

| 步骤 | 形状 | 语义 |
| --- | --- | --- |
| 输入与三个投影 | `[B,T,D]` | 每个位置的模型表示 |
| 拆头并交换轴 | `[B,H,T,d_h]` | 每个头独立处理序列 |
| `q @ k.transpose(-2,-1)` | `[B,H,T,T]` | Query 位置 × Key 位置 |
| 归一化注意力权重 | `[B,H,T,T]` | 每个 Query 对候选 Key 的分布 |
| `weights @ v` | `[B,H,T,d_h]` | 每个头的读取结果 |
| 交换轴、拼接各头 | `[B,T,D]` | 同一位置的所有头并排放置 |
| 输出投影 | `[B,T,D]` | 混合各头的通道信息 |

`[B,H,T,T]` 最后两个轴虽然长度相同，含义并不相同。倒数第二维表示“哪个位置发出查询”，最后一维表示“被查询的位置”。把序列长度 T 与头维度 $d_h$ 设成不同数值，有助于避免某些误换轴恰好因形状相等而不报错。本章快速配置为 T=5、H=3、$d_h$=4；常规配置为 T=7、H=4、$d_h$=6。

各头使用同一个位置序列，但学习不同的投影子空间。这给模型并行表示不同关系的机会，并不预先保证某个头负责语法、某个头负责指代。H 增大而 D 固定时，每头维度会缩小，不能把“头更多”直接等同于总表示容量线性增加。

## 因果掩码与 softmax 的轴

完整序列自注意力可以使用包含对角线的下三角矩阵。以 T=4 为例，`True` 表示允许读取：

```text
         key 0  key 1  key 2  key 3
query 0    1      0      0      0
query 1    1      1      0      0
query 2    1      1      1      0
query 3    1      1      1      1
```

为什么可以读取自身？输入位置 i 存放的是已经给定的当前 token，训练标签对应位置 i+1 的下一个 token。屏蔽对角线不是防泄漏所必需，反而使位置 0 没有任何可读 Key；如果整行都是负无穷，softmax 通常得到 NaN。只有标签或目标的具体定义发生变化时，才应重新推导允许关系。

手工实现如下：

```python
scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
allowed = torch.ones(T, T, dtype=torch.bool).tril()
scores = scores.masked_fill(~allowed, float("-inf"))
weights = scores.softmax(dim=-1)
z = weights @ v
```

`allowed` 的 `[T,T]` 通过广播作用于所有 batch 和头。我们替换不允许位置的分数，而不是把分数乘零：零经过指数会变成一，仍然分到概率。使用负无穷会使这些指数变成零。在每行至少有一个有效位置的前提下，softmax 可稳定地减去行最大值再计算。代码直接调用框架实现，无需自行写不稳定的 `exp/sum(exp)`。

对每个 Query i，应该在所有 Key j 上竞争概率，因此 `softmax(dim=-1)`。若写成 `dim=-2`，就变成每个 Key 在 Query 位置间归一化。这个输出仍然有限、矩阵乘法仍合法，甚至未来权重仍可全为零，但每行的和不再为一，含义已经改变。因此“没有泄漏”和“算对注意力”是两类不同的要求。

同一个布尔值在不同 API 中可能含义相反。手工 `masked_fill` 中，True 表示要填充的位置；本章的变量 `allowed` 则用 True 表示允许，因此必须取反。`F.scaled_dot_product_attention` 的布尔 `attn_mask` 中 True 表示可参与计算，而 `nn.MultiheadAttention` 的一些 mask 参数约定不同。查对应版本接口文档，不要仅凭 `mask` 这个名称猜测。

## 合头为什么不能省略 transpose

注意力内核的输出是 `[B,H,T,d_h]`。要把同一位置的 H 个头接在一起，先变成 `[B,T,H,d_h]`，再合并最后两维：

```python
z = z.transpose(1, 2).contiguous().reshape(B, T, D)
y = z @ wo
```

`transpose` 改变轴的逻辑次序，`contiguous` 使接下来展示的内存布局直观。`reshape` 在需要时也可能复制，但不会替你推断哪个轴应先交换。如果直接把 `[B,H,T,d_h]` reshape 成 `[B,T,D]`，结果形状完全正确，元素却按错误的头与位置关系组合。本章专门保留这种错误的负向对照。

输出投影 $W_O$ 在每个位置分别混合各头通道，不跨位置计算。因而只要前面的注意力是因果的，输出投影不会引入未来依赖。注意这个结论来自线性层在位置维上共享且独立应用的结构，不是因为最终 shape 与输入一样。

本章四个 D×D 投影共有 $4D^2$ 个参数。注意力分数张量有 $BHT^2$ 个元素，分数与 Value 聚合的主要运算随 T 的平方增长；投影的开销则包含 $BTD^2$。这些数量用于理解计算结构，不是实测延迟。后面性能章节会讨论为何实际内核可能不显式存下完整分数矩阵，也会区分数学复杂度与硬件运行时间。

## 如何构造可信的参考比较

只比较最终输出还不够：训练依赖反向传播。脚本为输入 X 和四个投影矩阵分别创建两套数值相同、计算图独立的叶子张量。第一套执行手工注意力，第二套使用 PyTorch 的 `F.scaled_dot_product_attention`，其他投影、拆头、合头步骤保持相同。

参考分支调用时固定 `dropout_p=0.0`、`is_causal=True`。SDPA 的函数接口即使在外部模块处于 eval 时也会按传入概率施加 dropout，因此应显式传零。本章不使用随机 dropout，保证对照比较的是同一函数。

我们取一个固定随机的上游张量 U，让损失为所有输出与 U 的逐元素内积：

$$
L=\sum_{b,t,d}Y_{btd}U_{btd}.
$$

再分别求出对 X、$W_Q$、$W_K$、$W_V$、$W_O$ 的梯度，并比较最大绝对误差。使用非全一的上游梯度，有助于避免只对某些通道求和恰好隐藏错误。这里不检查优化器和训练曲线，因为它们不是注意力算子的最小验证条件。

两条路径在 Float64 CPU 条件下使用 $10^{-10}$ 的绝对误差门槛。这个阈值面向本章小尺度随机张量，不应原样移到 FP16、BF16、长序列或其他设备；那些场景需要重新考察误差随量级、归约次序和内核变化的情况。参考分支本身也不是数学证明，仍需结合结构性质与反例检查。两份代码可能共享同一个错误，不能只靠“它们相等”就宣布实现正确。

## 用扰动与梯度验证因果性

将序列在边界 $c=\lfloor T/2\rfloor$ 分成两段。保持前缀 $X_{:, :c}$ 不变，只修改后半段 $X_{:, c:}$。使用同一套参数执行两次前向，要求输出前缀一致，后缀至少有可测变化。

前缀一致验证了“变化不能从未来传回来”。后缀确实变化则排除一些过弱检查：例如输出恒零的错误实现也会通过前缀一致。脚本还移除掩码再执行同样的扰动，确认这时前缀会改变。这个负向对照表明当前数据和扰动足以暴露缺少掩码的问题。若移除掩码仍无差异，应先检查权重、Value 或扰动是否退化，不能把这次对照视为有检测能力。

另一种检查来自导数。令损失只依赖输出前缀，则输入后缀不应存在从该损失返回的梯度路径：

$$
\frac{\partial L(Y_{:, :c})}{\partial X_{:, c:}}=0.
$$

脚本通过 autograd 实际验证该梯度为零。它与数值扰动互补：扰动检查实际函数值的变化，梯度检查当前位置的局部依赖。在这个由线性投影、softmax 与掩码组成的模块中，两者共同提供清晰的证据。不要将一次导数为零等同于任意非线性系统都没有依赖；饱和或特定输入也可能造成局部零梯度。

先按[实验运行指南](/labs)准备 PyTorch 环境。如果只拿到脚本，也可在自己的虚拟环境安装 CPU PyTorch 后运行。仓库根目录下的调用是：

快速与常规模式都执行同样的 13 项检查。区别仅在 B/T/D/H 配置，用来以另一组形状复核实现。`--seed` 同时控制输入、投影、上游梯度和扰动；更换 seed 是增加样例覆盖，不是统计意义上的模型训练实验。

| 检查组 | 实际验证内容 |
| --- | --- |
| 输出与数值 | shape 正确；前向与梯度均有限 |
| 参考等价 | SDPA 前向一致；输入及四个投影梯度均一致 |
| 权重分布 | Key 轴和为一；未来权重为零；第一 Query 只读第一 Key |
| 因果依赖 | 未来扰动不改前缀；可见后缀会变化；前缀损失对未来输入梯度为零 |
| 负向对照 | 无 mask 会泄漏；错误 softmax 轴可检测；漏掉合头 transpose 可检测 |

本次实际执行的 CPU 环境为 PyTorch 2.8.0+cpu、Float64。seed 42 的 quick 模式全部 13 项通过，前向最大绝对误差约 $4.44\times10^{-16}$，五组梯度的最大误差不超过 $2.00\times10^{-15}$；因果前缀差异与未来输入梯度均为零。移除掩码后，前缀最大变化约 3.50，说明负向对照确实触发。常规模式及 quick seed 7 同样通过 13 项检查。它们是这些实际配置下的验证记录，不保证其他实现、精度和设备产生逐位相同结果，也没有测量任何 GPU 加速比。

读取结果时先检查 `checks`，再看 `metrics`。例如 `wrong_softmax_row_sum_max_abs_error` 很大是有意构造的错误实现被检测到了，并不是正确路径失败。负向对照的指标需要结合字段含义解释，不能把所有数值都机械地要求越小越好。

## 易错点与诊断顺序

发现输出对不上时，先打印每个轴的语义，再检查 mask 与 softmax，最后检查合头和投影。不要立即放宽误差阈值。轴顺序错误通常产生远超舍入误差的差异；提高容忍度只会掩盖错误。

若输出包含 NaN，优先看某个 Query 是否整行被 mask，以及未屏蔽分数是否已经非有限。不要用 `nan_to_num` 直接替代根因修复。若训练时 loss 异常好，先检查标签移位和未来依赖，模型读取了目标答案也能得到漂亮曲线。若前向相等而梯度不同，则检查是否意外 `detach`、复制到不保留计算图的张量，或只比较了 Value 路径而漏掉 Q/K 路径。

最后记住本章 mask 的边界。KV Cache 推理时 Q 长度可能为 1、K 长度却是已有前缀加当前 token 的长度，此时简单拿 `[Q_len,K_len]` 的左上角下三角并不总表达正确的绝对位置关系。存在 padding、不同长度 batch、滑动窗口时，也必须重新推导允许矩阵。第 08 章会专门处理缓存的偏移与分块问题，本章通过不代表那些情况已验证。

## 练习与提示

1. 把手算例子的两个分数改成 $[0,\log 3]$，算出权重和输出。提示：指数后的比例是 1:3，先归一化再聚合 Value，最后检查权重和。
2. 在自己的实验副本中把 softmax 轴改错，列出哪些检查能发现、哪些仍能通过。提示：因果掩码仍可能让未来权重为零，但沿 Key 的概率和会改变。
3. 去掉 `merge_heads` 中的 transpose，解释为什么最终 shape 检查仍通过。提示：用只有一个非零元素的小张量追踪它在 `[H,T,d_h]` 与 `[T,H,d_h]` 中的位置。
4. 加入 bias 并扩展梯度对照。提示：三种输入投影 bias 形状是 `[D]`，输出 bias 也是 `[D]`；两条路径必须接收相同的参数副本，不能只在一个分支加入。
5. 把因果矩阵改为每个 Query 最多读取最近 W 个位置，先手画 T=5、W=2 的允许关系，再写检查。提示：同时满足 $j\le i$ 与 $j\ge i-W+1$，位置 0 仍应能读自身。
