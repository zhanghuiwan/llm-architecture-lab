# 统一实验规范

每次改变网络结构之前，先写清要回答的问题。本页可作为训练记录与架构报告的检查清单。

## 选择主要预算

| 约束 | 适合回答的问题 | 需要额外记录 |
| --- | --- | --- |
| 相同训练 Token | 接触相同数量 Token 后的表现 | 参数、计算、时长 |
| 相近 FLOPs | 计算预算下的建模效率 | FLOPs 估算口径、实际时长 |
| 相同硬件与时间 | 实际资源限制下的收益 | 有效 Token、吞吐、数据管线 |
| 相同推理约束 | 满足延迟或显存条件的方案 | 批量、长度、缓存与采样 |

这些条件通常无法同时严格满足。指定一个主要约束，如实记录其他差异，不通过隐含改变训练量来制造公平比较。

## 固定或报告的条件

- 模型配置、总参数、激活参数的统计口径与代码版本。
- 数据版本、Tokenizer、文档边界、去重与样本顺序。
- 序列长度、有效批量、训练 Token 与学习率曲线。
- 优化器、精度、梯度裁剪、初始化、随机种子。
- 验证指标、生成配置、性能计时与显存测量方法。

## 先通过正确性检查

因果性、标签对齐、小数据过拟合、实现数值对照、缓存与完整前向的一致性，应按实验范围执行。未通过的检查不能靠更长训练或漂亮的生成样本替代。

## 控制随机性与调参预算

小预算可先筛选方向，再对候选方案使用多个随机种子。先使用相同配方可以观察直接替换的结果；若各方案分别调参，需约束并报告调参预算。不要把训练稳定性与超参数适配问题全部归因于结构表达能力。

## 什么可以公开

公开可复现的配置、源码版本、检查结果、测量条件与经过许可的数据获取方式。不要上传私有数据、凭据或受限制的权重。负面结果与未完成项也应保留明确标记。
